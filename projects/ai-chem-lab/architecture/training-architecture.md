# 训练架构详解

> **对应问题**：训练什么模型？用什么方法训练？触觉数据怎么用？模型底层自建还是基于 VLA？
> **日期**：2026-07-24

---

## 一、需要训练的模型（共 3 个）

整个架构中，需要数据训练的是 3 个模型，不是 1 个。

```
┌──────────────────────────────────────────────┐
│  ① 场景感知模型 (Scene Perception Model)      │   ← 可选训练（可用基座+微调）
├──────────────────────────────────────────────┤
│  ② 技能策略模型 (Skill Policy Model)          │   ← 核心训练（需要大量数据）
├──────────────────────────────────────────────┤
│  ③ 技能选择/排序模型 (Skill Selector)          │   ← 轻量训练（少量数据即可）
└──────────────────────────────────────────────┘
```

### ① 场景感知模型

**用途**：从相机图像中识别所有实验物体，输出 3D 位姿

**训练方式**：**监督学习（不是 RL）**

- 基座模型：SAM2（分割一切）+ DINOv2（特征提取）
- **不从头训练**，用已有预训练权重
- 只在你的实验室场景数据上做 **小样本微调 (few-shot fine-tuning)**
  - 拍 100-500 张实验室照片
  - 标注：烧杯、微量杯、刮刀、移液枪、瓶盖……
  - 微调 Detection Head

**数据集规模**：500-2000 张标注图即可

**触觉数据参与？** ❌ 不需要，纯视觉模型

---

### ② 技能策略模型 ← 核心，最复杂

**用途**：给定目标物体姿态 → 生成机器人的关节运动轨迹

**这才是主力训练对象。触觉数据也喂给它。**

#### 训练方法：**不是纯 RL，是行为克隆 (BC) + RL 混合**

```
           ┌──────────────────┐
           │  初始训练阶段      │
           │  行为克隆 (BC)     │   ← 模仿学习
           │  来源：人手示教    │
           │  + 触觉手套数据   │
           └────────┬─────────┘
                    ↓
           ┌──────────────────┐
           │  优化训练阶段      │
           │  强化学习 (RL)     │   ← 在 MuJoCo 仿真中优化
           │  奖励函数设计      │
           │  来源：仿真自练    │
           └────────┬─────────┘
                    ↓
           ┌──────────────────┐
           │  真机微调阶段      │
           │  少量真机数据      │
           │  弥合 sim-to-real  │
           └──────────────────┘
```

**为什么不是纯 RL？**

| 方法 | 优点 | 缺点 |
|------|------|------|
| 纯 BC（行为克隆） | 学得快，直接模仿人 | 泛化差，没见过的情况就懵 |
| 纯 RL | 泛化好，能自己探索 | 训练极慢，百万级步数才收敛 |
| **BC → RL 混合** | 先学人，再自己优化 | 最佳实践，业界主流 |

**触觉数据怎么用？**

```
人手示教采集：
  人戴触觉手套操作
  ↓
  时间同步记录：
  ├── 关节角度 (从机器人回读)
  ├── 触觉压力 (124 点，从手套读取)
  └── 摄像头图像
  ↓
  训练时：
  技能策略模型输入 = 图像 + 当前关节角度 + 【触觉编码】
                                    ↑
                            这是我们额外加的信号
```

**触觉的作用**：
- 在人手示教阶段：提供"人用了多大劲"的参考信号
- 在 RL 阶段：MuJoCo 仿真中合成虚拟触觉信号
- 在真机执行时：**触觉作为闭环反馈**，实时修正 grip force

**数据集规模**：
- BC 初始：每个技能 500-2000 次示教（人手采集）
- RL 优化：仿真中 10 万-100 万步（GPU 加速，MJX 几分钟跑完）
- 真机微调：50-200 次

---

### ③ 技能选择模型（Skill Selector）

**用途**：给定场景和任务，选哪个技能来执行

**LLM 已经做了最高层的任务分解**（给出一串 skill ID），但到具体执行时还需要一个**轻量的选择器**来决定：
- pick 用哪个抓取姿态？（上抓 / 侧抓 / 二指 / 三指）
- pour 的速度多少？
- 当前场景如果有微小变化（物体偏移 1cm），调不调？

**训练方法**：**监督学习 + 规则**（非常轻量）
- 本质是一个小分类器 + 规则引擎
- 不需要大模型
- 可以手写规则 + 少量数据微调

## 二、触觉数据流向全景

你说得对——**触觉数据主要喂给技能策略模型**，但完整流向如下：

```
采集阶段（人手示教）：
  触觉手套 124 点 → 编码器 (VQ-VAE+CNN) → 编码向量 (128维)
  ↓
  和图像/关节角度/IMU 同步打包 → 一条完整训练样本

训练阶段：
  编码后的触觉向量 → 作为 skill policy 的额外输入通道
  └→ 技能策略模型学会"多大压力对应什么动作"

执行阶段：
  灵巧手触觉传感器 (Dex3-1 33点) → MCU 本地力控闭环
  同时回传编码后的触觉数据 → 服务器记录
  └→ 长期积累 → 用来训练更好的力控策略
```

**关键认识**：
- 触觉在**训练阶段**：作为学习信号（人教的力该多大）
- 触觉在**执行阶段**：作为力控闭环的反馈信号（实时调整 grip force）
- 触觉不喂给 LLM，也不喂给场景感知模型

## 三、模型底层——用 VLA 还是自建？

好问题。实际答案是：**用 VLA 的思想，但不走 LabVLA 的端到端路线**。

### 核心策略：模块换芯

```
LabVLA 的做法（端到端）：
  Qwen3-VL-4B(视觉语言) + DiT(动作头)
  → 一个模型包揽全部

我们的做法（分层）：
  ① 场景感知 = SAM2 + DINOv2（开源基座）
  ② 技能策略 = Diffusion Policy（开源基座）
  ③ 技能选择 = MLP + 规则（自建，几百行）
```

### 每个模型的底层

| 模型 | 基座 | 来源 | 训练成本 |
|------|------|------|---------|
| ① 场景感知 | SAM2 + DINOv2 | Meta 开源 | 免费，只需微调 |
| ② 技能策略 | **Diffusion Policy** (Chi et al.) | 开源 | 需训练 |
| ③ 技能选择 | 简单 MLP + 规则引擎 | 自建 | 几乎零成本 |

**Diffusion Policy 是什么？**
- 2023-2024 年机器人领域最成功的动作生成方法之一
- 核心思想：把动作生成类比为"图像去噪"
- 输入当前状态 → 随机噪声 → 逐步降噪 → 得到优化轨迹
- 已被多个实验室验证：稳定性好、多峰分布（多种可行动作都能学）
- 与 VLA 不是对立关系，Diffusion Policy 可以接在 VLA 后面当动作头

### 用 Diffusion Policy 而不是 VLA 做技能策略的原因

| 对比项 | Diffusion Policy | VLA 动作头 (DiT) |
|--------|----------------|------------------|
| **训练数据需求** | 几百次示教即可 | 万级起步 |
| **动作精度** | 可通过条件控制精细 | 粗粒度 |
| **触觉融合** | 加个输入通道即可 | 需要改模型架构 |
| **力控支持** | 可输出力矩 | 通常只输出位置 |
| **可解释性** | 中（可看噪声过程） | 低（端到端黑盒） |
| **社区成熟度** | 高（多个知名项目用） | 中（LabVLA 特有） |

## 四、TL;DR 总结

> **训练的不是一个大模型，是三个分工明确的小模型**

| # | 模型 | 训练方法 | 触觉参与？ | 底层 |
|---|------|---------|-----------|------|
| ① | 场景感知 | 微调（不是训练） | ❌ | SAM2 + DINOv2（Meta 开源） |
| ② | 技能策略 | **BC + RL 混合** | ✅ **核心输入** | Diffusion Policy（开源） |
| ③ | 技能选择 | 规则 + 少量监督 | ❌ | 自建，十分轻量 |

> **触觉训练数据 → 全部喂给技能策略模型（不是 LLM，不是场景感知）**

> **模型底层不是 LabVLA 的端到端路线，而是 Diffusion Policy + 经典控制的分层路线**
>
> VLA 的"视觉理解+语言+动作"大一统思路不适合精密化学实验。
> 拆开做：纯视觉模型负责"看"，Diffusion Policy 负责"动"，LLM 负责"想"。

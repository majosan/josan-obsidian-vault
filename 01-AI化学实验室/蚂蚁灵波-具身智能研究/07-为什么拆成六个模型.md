# 为什么拆成六个模型，而不是做1个大的？

> 相关笔记：[[六模型全景解读]] | [[VLA与VA对比与切换逻辑]]

**最直白的答案：强行合并会变得很难用、很大、很慢。**

---

## 原因①：架构底层完全不同

| 模型 | 核心架构 | 类比人类 |
|------|---------|---------|
| Vision | ViT（视觉Transformer） | 视觉皮层（只看不碰） |
| Depth | 密集预测（U-Net/CNN） | 立体视觉区（算距离） |
| VLA | 解码器Transformer | 大脑皮层（做决策） |
| VA | 自回归扩散 | 小脑+运动皮层（下意识动作） |
| World | 扩散模型+因果预测 | 想象/预演 |
| Video | 视频扩散/VAE | 做梦/想象（全脑模拟） |

这些架构的**数学本质不同**：
- ViT处理2D空间网格（图像）
- Transformer处理1D token序列（语言+动作）
- 扩散模型要一次次去噪（视频生成）
- U-Net要做像素级密集预测（深度图）

强行放一起→巨无霸模型→既做不好视觉，也做不好决策。
**"one model to rule them all, one model to do none well"**

---

## 原因②：训练数据要求不同

| 模型 | 需要的数据 | 数据量级 |
|------|-----------|---------|
| Vision | 普通RGB图片+标注 | 亿级 |
| Depth | RGB-D图片+深度标签 | 百万级 |
| VLA | 真机操作数据 | 万/十万小时 |
| VA | 视频+动作标签 | 千万小时视频 |
| World | 交互式物理模拟数据 | 特别难采 |

混在一起训练→"这张猫图是教Vision看东西，还是教VA怎么动？"
→ 模型困惑→梯度冲突→训练不稳定→**哪个都学不好**

---

## 原因③：部署位置和延迟不同

| 部署位置 | 跑的模型 | 延迟要求 |
|---------|---------|---------|
| 机器人本体（Orin端侧） | VLA（~100ms） | 🏃 极快 |
| 机器人本体 | Depth（~50ms） | 🏃 极快 |
| 机器人本体 | Vision（~30ms） | 🏃 极快 |
| 边缘服务器 | VA（~300ms） | 🚶 可慢一点 |
| 云端 | World（~秒级） | 🧘 可很慢 |

一个模型没法同时部署在端侧和云端——端侧放不下大模型，云端延迟无法接受。

---

## 原因④：迭代速度不同

```
Depth模型更新 → 只影响感知 → 不影响决策 → 可单独测试上线
VLA模型更新 → 影响动作决策 → 需要全面回归测试
World模型 → 离线用 → 随时升级不影响真机

一个模型：改一行代码 → 全部重训 + 全部重测
六个模型：只改Depth → 只训Depth → 只测Depth
```

---

## 那怎么"组装"？Brain Orchestrator

蚂蚁通过一个**隐形的"编排层"**来组装六个模型：

### 当前状态：规则驱动

```
if 任务类型 == "单步操作":  路由到 VLA
if 任务类型 == "时序追踪":  路由到 VA
if 需要评估:               调用 World
if 新建实验:               重新编排流程
```

### 未来方向：学习驱动

训练一个小模型（Router Agent）：
- 输入：当前状态 + 任务描述
- 输出：调用哪个模型 + 参数

# 🧠 FTP-1 论文深度解读

## 一、背景：为什么 FTP-1 是里程碑式的？

之前触觉策略全是"专机专用"——换一个传感器就要从头训。视觉领域已经有通用基础策略（π0.5、OpenVLA 等），但触觉一直没有。

原因很直接：**触觉信号极度异构**。GelSight 输出图像（RGB），你的织物传感阵列输出 32×32 数值矩阵，力传感器输出 6 轴 F/T 值——这仨完全是不同的模态，没法直接用一套网络处理。

FTP-1 的贡献就是：**第一次让一个触觉策略能在不同传感器、不同机器人本体之间迁移**。

---

## 二、架构核心：三个关键设计

### ① MTTS — 形态感知触觉 Token 空间（论文核心创新）

FTP-1 定义了一个**统一的触觉接口**，将任何传感器的信号映射到同一组"功能区域"Token 上：

Copy

```
24 个功能区域槽位：
  slot 0-14:  手指功能区域（拇指尖、食指尖、掌心……）
  slot 15-20: 腕部/指部力传感器
  slot 21-23: 预留
```

**对你特别有参考价值**: 平行夹爪的两个传感器 → 映射到 slot 0（拇指）和 slot 1（食指）。这种"功能对等映射"的思路，你的 32×32 阵列也可以做类似的区域定义。

### ② 异构编码器 → 统一 Token

FTP-1 针对三类输入分别设计了编码器：

|输入类型|示例|编码方式|
|---|---|---|
|**图像型 (Image)**|GelSight 触觉相机|ViT + 共享 T3 Transformer → [CLS] token|
|**阵列型 (Array)**|Contactile、**你的 32×32 织物阵列**|CNN → 捕获空间触觉结构 → 每个功能区域压缩为 1 个 token|
|**状态型 (State)**|力/力矩传感器|Fourier 编码 + MLP|

**你的定位很明确**：你们的织物传感阵列属于 **Array-type**，FTP-1 用 CNN 处理这类信号。这是最容易对齐的路线。

### ③ 独立触觉专家模块（Tactile Expert）

FTP-1 的架构是 **多专家架构**，基于 Physical Intelligence 的 π0.5（视觉-语言-动作模型）：

Copy

```
视觉-LM Expert（PaliGemma 3B）
      ↓  attention
触觉 Expert（300M Transformer）
      ↓  attention  
动作 Expert（Flow Matching Transformer）
      ↓
      action
```

关键对比之前的 Tactile-VLA（直接把触觉 token 注入 VLM）——FTP-1 的独立 Tactile Expert 设计明显更好：

- ✅ 不干扰预训练的视觉-语言知识
- ✅ 微调时可以替换触觉编码器，但复用共享的 Tactile Expert
- ✅ 触觉处理效率更高

## 四、实验结果：硬数据

### 已见传感器（3 套硬件，14 个任务）

|对比方法|UniVTAC 仿真|实物平均|
|---|---|---|
|π0.5（无触觉）|42%|45.3%|
|Tactile-VLA（注入式）|~42%|~35%|
|FTP-π0.5（有架构无预训练）|42%|30%|
|**FTP-1**|**59.5%**|**62.5%**|

比第二名高 **+17.5%**，排除 lift 这类视觉就能解决的任务后差距更明显。

### 未见过的传感器（跨机构验证，最有说服力）

FTP-1 分发到**两家新机构**，传感器在预训练中完全没出现过：

|任务|传感器|π0.5|Tactile-VLA|FTP-π0.5|**FTP-1**|
|---|---|---|---|---|---|
|Insert Hanoi|Xense 图像型|24%|8%|12%|**50%**|
|Insert USB|Xense 图像型|8%|0%|0%|**30%**|
|Wipe Board|Contactile 阵列型|15%|10%|10%|**60%**|
|**平均**||15.7%|6%|7.3%|**46.7%**|

**+31% 提升**，而且表现出"恢复行为"——出错后能感应触觉反馈自行纠正。

### 消融实验：确认真的是"触觉预训练知识"在起作用

他们做了一个 NTP-1（用同样的数据，但预训练时**不加触觉输入**），然后在未知传感器上对比：

- NTP-1 在已见传感器上比 π0.5 好（因为数据分布更近）
- **但在未知传感器上，FTP-1 比 NTP-1 高 +37.5%** ——说明不是数据分布问题，而是**触觉 branch 确实学到了可迁移的触觉操作知识**

## 五、对你的 32×32 织物传感阵列的参考意义

### 可以直接复用的思路

1. **阵列型编码器路线**：FTP-1 用 CNN 处理阵列触觉输入。你的 32×32 就是标准的 2D 网格，直接对齐。可以基于 FTP-1 的代码（基于 OpenPI）做微调适配。
    
2. **功能区域映射**：MTTS 的 24 个功能区域定义你可以直接套用——你的 32×32 传感点可以按位置分组映射到不同功能区域。比如：
    
    - 传感器中心区域 → slot 0-1（指尖类）
    - 边缘区域 → slot 14（掌心类）
    - 这个映射不需要太精确，FTP-1 的设计就是允许功能对等映射的
3. **微调流程**：保留 FTP-1 的预训练 Tactile Expert 权重，只替换你的传感器编码器部分。他们开源了完整的 fine-tuning pipeline。
    
4. **"未见传感器"验证路线**：FTP-1 证明了即使用不同的传感器，预训练知识也能迁移。这意味着你未来开发 SKU-1（500×500mm）和 SKU-2（1400×700mm）时，理论上可以用同一套模型微调两个版本。
    

### 需要自己搞的部分

- **数据采集**：FTP-1 的预训练数据是 ~3000 小时的操作示教。你的场景（智能床垫/医疗养老）需要自己采集对应场景的触觉数据
- **触觉手套对接触觉策略**：你们的触觉手套有 124 个传感点，FTP-1 主要做抓握操作策略（灵巧手/夹爪），你如果要用在医疗养老场景，可能需要微调下游任务的侧重点

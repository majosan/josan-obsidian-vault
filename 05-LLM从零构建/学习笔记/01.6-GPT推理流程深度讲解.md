# 🚀 GPT 推理流程深度讲解 — 从输入到输出的 6 步全流程

> **前置**：配合 `GPT推理流程全景.canvas` 一起看效果最好
> **定位**：把 Canvas 上每个节点串起来讲透，让你看完就知道模型"内部到底怎么跑的"

---

## 整体流程一览

```
你输入 "我爱"
  → ① Tokenizer (BPE切词 → Token ID)
  → ② Embedding (ID变768维向量)
  → ③ Positional Encoding (加位置码)
  → ④ Transformer Block × 12 (核心算力)
       ├─ ④a Multi-Head Attention (12头并行收集上下文)
       ├─ ④b Add & LayerNorm (稳定信号)
       ├─ ④c Feed-Forward (独自深加工)
       └─ ④d Add & LayerNorm (再次稳定)
  → ⑤ 重复12层
  → ⑥ 线性映射 + Softmax (输出概率 → 选下一个词)
  → 循环 → 生成长文本
```

---

## Step 0: 模型先加载

你打开 ChatGPT（或本地跑 LLM），第一步是加载模型权重：

- GPT-2 Small 的权重文件约 **500MB**
- 里面存了 **1.24 亿个参数**的数字
- 加载到显存（RTX 4060 8GB 完全够跑 GPT-2 Small）
- 模型进入"待命"状态，等待输入

> 💡 **本质**：一个训练好的神经网络从硬盘读到内存/显存，变成一个**可执行的函数**。
> 输入文本 → 输出下一个词的概率分布。

---

## Step 1: Tokenizer (BPE) — 把"人话"变成"编号"

你写了 `"我爱"`，但电脑只认数字。Tokenizer 就是那个把文字切碎、编号的翻译官。

### 为什么需要切碎？

```
"我爱" → word 级切分 → ["我", "爱"] → [123, 456]

但遇到生词怎么办？
"ChatGPT" → 不在词表里 → ❌ 错误（word 级的问题）

BPE 方案（GPT 用的）：
"ChatGPT" → ["Chat", "G", "PT"] → 都在词表里 ✅
```

### BPE（Byte Pair Encoding）核心思想

1. 先把所有词拆成**单个字符**
2. 统计**最常出现的字符对**，合并成一个子词
3. 重复合并，直到词表达到目标大小

GPT-2 的词表大小：**50,257**

### 你输入 "我爱" 后

```
Tokenizer 查表 →
"我" → ID: 123
"爱" → ID: 456
输出: [123, 456]
```

> 🎯 **Ch2 实操**：你会亲手跑 GPT-2 的 BPE Tokenizer，
> 看到 `"我爱"` 输入确实输出了两个 ID。

---

## Step 2: Embedding 层 — ID 变向量

现在模型拿到了两个数字：`[123, 456]`。但 **123 这个数字本身没有意义**——123 是"我"还是"猫"？

Embedding 层的任务：**把 ID 转成有语义的向量**。

### 一张巨大的表格

```
词表 (50,257 行) × 嵌入维度 (768 列)
        列1    列2    列3    ...  列768
ID 1:  [0.23, -0.87, 0.14, ..., 0.55]     ← "！"
ID 2:  [0.45, 0.12, -0.33, ..., 0.21]     ← "的"
...
ID 123: [0.67, -0.34, 0.89, ..., -0.12]   ← "我"
ID 456: [-0.23, 0.78, -0.45, ..., 0.33]   ← "爱"
```

### 查表过程

- ID 123 → 读出第 123 行那 768 个数 → 这就是"我"的向量表示
- ID 456 → 读出第 456 行那 768 个数 → "爱"的向量表示

**输出**：一个 `2 × 768` 的矩阵（2 个词，每个 768 维）

### 为什么是 768？

- 768 维：每个词用 **768 个数字**来描述
- 维度越高描述越精细，但计算量也越大
- GPT-2 选 768 是 2018 年的工程权衡

### 这些数字怎么来的？

**不是人写的，是训练学出来的！**

预训练过程中，模型发现：
- "我"和"你"向量接近（都是人称代词）
- "猫"和"狗"向量接近（都是动物）
- "猫"和"冰箱"向量很远
- **"国王 - 男人 + 女人 ≈ 女王"**——向量可以做语义加减法！

> 🔥 **关键**：Embedding 层是可训练的。一开始全是随机数字，
> 训练几十亿 tokens 后，它们学会了**语义空间的结构**。

---

## Step 3: Positional Encoding — 告诉模型"顺序"

### 问题

Embedding 本身**没有顺序概念**：

```
输入 "我爱" → Embedding → [v_我, v_爱]
输入 "爱我" → Embedding → [v_爱, v_我]
```

**"我爱"和"爱我"的 Embedding 是一模一样的向量，只是交换了位置。**

但模型做 Attention 时，这两个完全不同的含义需要区分。

### 解决方案：加一个位置码

```
"我"（位置1）:
  [0.67, -0.34, 0.89, ...] + [0.01, 0.01, 0.01, ...]
  = [0.68, -0.33, 0.90, ...]   ← 带位置信息的向量

"爱"（位置2）:
  [-0.23, 0.78, -0.45, ...] + [0.02, 0.03, 0.01, ...]
  = [-0.21, 0.81, -0.44, ...]
```

### GPT 用的方案（绝对位置编码）

- 位置 1 有固定编码向量，位置 2 另有固定编码向量……
- 像"位置版的 Embedding"，模型学出来的
- **限制**：训练时最多看 1024 个位置（上下文长度）

### 更先进的方案（RoPE - LLaMA/Qwen 用的）

- 通过**旋转矩阵**编码位置
- 可外推到没见过的长度（训练 4096，推理 8192）
- 还能编码相对位置（"距离 3 个词"比"位置 5"更有用）

> 🎯 **Ch3 实操**：你会在 Ch3 亲手实现位置编码。

## Step 4: Transformer Block — 核心算力

输入是一组向量：`2 × 768`（2 个词，每个 768 维）。

它会经过 **4 个子步骤**。

---

### Step 4a: Multi-Head Attention（多头注意力）

**这是整个 Transformer 的核心创新。**

#### 先理解单个 Attention 头

```
Q = "我" × W_Q → Query:  "我在找什么？"
K = "爱" × W_K → Key:     "你是什么内容？"
V = "爱" × W_V → Value:   "你有什么信息？"

"我"跟"我"匹配度 = 0.8（自己当然相关）
"我"跟"爱"匹配度 = 0.9（"我"跟"爱"关系密切）

结果 = 0.5 × V("我") + 0.45 × V("爱")
     = 加权提取了上下文信息
```

**每个词都做一次，结果每个词都收集了上下文信息。**

#### 为什么叫"多头"？

一个头只能发现一种关系。多个头并行：

```
头 1: 关注语法关系 → "我"和"爱"是主语-动词
头 2: 关注语义修饰 → "快"修饰"跑"
头 3: 关注代词指代 → "它"指代"猫"
头 4: 关注实体关联 → "马斯克"和"特斯拉"
头 5-12: 更多关系...
```

12 个头各算各的，最后拼起来 → 12 × 64 维 = 768 维

#### 类比：12 人专家评审团

```
你（"我"）站在台上做汇报：
- 语法专家（头1）关注你的表达逻辑
- 语义专家（头2）关注你的用词准确度
- 上下文专家（头3）关注前后一致性
- ...

12 个专家各自打分，加权汇总 → 一个全面的评价
```

#### 为什么 Attention 这么重要？

在 Attention 发明之前，RNN/LSTM 处理长文本时：
- 必须**按顺序逐个处理**（慢，不能并行）
- 两个词距离越远，信息越难传递（遗忘问题）

Attention **一步到位**——每个词直接看所有词，没有距离衰减。

> 💡 **关键**：QKV（Query-Key-Value）概念来自**搜索引擎**——
> 你搜索"猫"，用 Query（搜索词）去匹配 Key（页面标题），
> 找出最相关的 Value（页面内容）。Transformer 借用了这个思想。

---

### Step 4b: Add & LayerNorm — 防止"学废了"

**残差连接（Add）**：

```
输出 = 输入 + 注意力层的输出
     = 原始信息 + 新学到的信息
```

就像一个贴了便利贴的书：**不管上面写什么，最底下的原文还在**。
即使某一层学偏了，原始信息还能传下去。

**LayerNorm（层归一化）**：
- 把每层的输出调整到**均值 0、方差 1**的分布
- 防止数值越传越大（梯度爆炸）或越传越小（梯度消失）
- 加速训练

---

### Step 4c: Feed-Forward — 每个词"独自思考"

Attention 阶段在"社交"（每个词看其他词）。

Feed-Forward 阶段**每个词独自思考**——对收集到的信息做深加工。

```
输入: 768 维向量（已包含上下文信息）
   ↓
第一层: 768 → 3072（扩展 4 倍，提取更丰富的特征）
   ↓
激活函数: ReLU（保留正信号，过滤负信号）
   ↓
第二层: 3072 → 768（压缩回原尺寸）
   ↓
输出: 768 维（更"深加工"后的表示）
```

**为什么需要这一步？**

```
Attention: 开会讨论（收集各方意见）
FFN:      回家写方案（消化吸收、产出结论）

两者缺一不可。
```

---

### Step 4d: Add & LayerNorm（再来一次）

同 Step 4b，作用完全一样——保护信息传递的稳定性。

**一个 Transformer Block 完成！** 输出：`2 × 768`。

---

## Step 5: 重复 12 层 — 深度堆叠

第 1 个 Block 的输出 → 第 2 个 Block 的输入 → 重复 12 次。

**为什么堆叠多层？**

```
第 1 层: 关注基础语法 —— 主谓宾
第 2 层: 关注语义 —— 谁做了什么
第 3 层: 关注逻辑 —— 因果关系
第 4 层: 关注情感 —— 语气倾向
第 5 层: 关注意图 —— 用户想干嘛
...
第 12 层: 综合所有信息，形成最"抽象"的理解
```

**层数越深，提取的特征越抽象、越高级。**

| 模型 | 层数 | 参数 |
|------|------|------|
| GPT-2 Small | 12 | 1.24 亿 |
| GPT-3 | 96 | 1,750 亿 |
| LLaMA-70B | 80 | 700 亿 |

---

## Step 6: 线性映射 + Softmax — 输出下一个词

经过 12 层 Transformer，模型对 `"我爱"` 的理解变成了高度抽象的 `768` 维向量。

现在要从中"读出"下一个词。

```
最后一层输出: 768 维向量（"爱"之后的表示）
    ↓
线性层: 768 → 50,257
  （每个词都有一个"分数"，表示它有多适合接在"爱"后面）
    ↓
Softmax: 分数转概率（所有词概率之和 = 1）
    ↓
输出:
  "你": 85%   ← 最高
  "他": 5%
  "吃": 3%
  "猫": 2%
  ...
    ↓
取概率最高的 → "你"
```

**生成结果**：`"我" + "爱" + "你" = "我爱你"`

然后**重复这个过程**：把 `"我爱你"` 作为输入 → 预测下一个词 → 继续重复 → 生成长文本。

---

## 总结：训练 vs 推理

以上讲的是**推理（Inference）**——模型已经训练好了，只是"用"。

| 阶段 | Loss & 梯度下降 | 作用 |
|------|---------------|------|
| **推理** | ❌ 没有 | 模型已固定，直接用参数算出输出 |
| **训练** | ✅ 有 | 比较输出和正确答案的差距 → 调整参数 |

**训练时多出来的步骤**：
1. 模型输出 → 和正确答案算 CrossEntropy Loss
2. 反向传播计算每个参数的梯度
3. 梯度下降（AdamW 优化器）更新参数
4. 重复数万亿次 → Loss 降到最低

**预训练 vs 微调**：走的是完全一样的 6 步流程，区别在于：
- **数据不同**：预训练用互联网通用文本，微调用问答对/指令对
- **起点不同**：预训练从随机权重开始，微调从预训练好的权重开始

## 🧠 Ch2 数据输入 Pipeline 精确理解

### 先说结论

> Tokenizer 把文字变成 ID（预处理），Embedding 层把 ID 变成向量（模型第一层），加上位置编码后一起喂给 Transformer。

### 常见误解纠正

**❌ 不对**：「文本 → tokenizer → 形成词汇表」
**✅ 正确**：「词汇表是在 BPE 训练阶段**预先生成**的（统计海量文本的频率），之后每次处理文本只是**查表**」

类比：词典是事先编好的，你查词的时候不是重新编词典。

### Pipeline 完整流程（精确版）

```
原始文本: "我爱编程"
     │
     ▼
┌─────────────────────────────┐
│① Tokenizer (BPE) — 查表    │ ← 词汇表已预训练好（50,257 个词）
│  "我" → ID 123               │
│  "爱" → ID 456               │
│  "编" → ID 789               │
│  "程" → ID 012               │
└──────────┬──────────────────┘
           ▼
Token IDs: [123, 456, 789, 012]
           │
           ▼
┌──────────────────────────────────────────┐
│② Embedding 层（nn.Embedding 查表）       │ ← 模型的第一层（可训练参数）
│  词表大小(50,257) × 嵌入维度(768) 的查找表  │
│                                          │
│  ID 123 → [0.67, -0.34, ..., 0.55]  ← "我" 的 768 维向量  │
│  ID 456 → [-0.23, 0.78, ..., 0.33]  ← "爱" 的 768 维向量  │
│  ID 789 → [0.45, 0.12, ..., -0.11]  ← "编" 的 768 维向量  │
│  ID 012 → [-0.55, 0.33, ..., 0.89]  ← "程" 的 768 维向量  │
└──────────┬───────────────────────────────┘
           ▼
Token Embeddings: 4 × 768 矩阵
           +
Positional Embeddings: 4 × 768 矩阵（位置0,1,2,3的编码）
           │
           ▼
③ Final Input: 4 × 768 矩阵 ← 送入 Transformer Block 的最终输入
```

### 关键数据类型变化

| 阶段 | 数据类型 | 形状示例 | 说明 |
|------|---------|---------|------|
| 原始文本 | 字符串 | "我爱编程" | 人读的 |
| 经过 Tokenizer | Token ID 数组 | [123, 456, 789, 012] | 整数列表 |
| 经过 Embedding | 浮点数矩阵 | 4 × 768 = 3,072 个数字 | 稠密向量 |
| 加位置编码后 | 浮点数矩阵 | 4 × 768 = 3,072 个数字 | 带位置信息的向量 |

### Ch2 视频/代码中需要关注的三个核心函数

1. **`GPTDatasetV1`** — 数据怎么被切成长度为 `context_length` 的块（Sliding Window）
   - 输入文本 → 切成 `block_size` 长度的重叠片段
   - `[t0, t1, t2, t3, t4]` 以 window=3 切 → `[t0,t1,t2]` 输入，`[t1,t2,t3]` 标签

2. **`create_dataloader_v1`** — DataLoader 怎么批量喂数据
   - batch_size × context_length 的数据块
   - 并行喂给 GPU

3. **Embedding 层的输出形状**
   - `nn.Embedding(vocab_size, emb_dim)` 实例化
   - 输入 ID → 输出 `[batch_size, seq_len, emb_dim]`

## 💡 项目映射思考

- BPE 的核心思想（统计频率合并子词）可以启发**触觉数据的"触觉 BPE"**
  - 频繁出现的压力模式 → 合并成"子词"
  - 少见的异常压力模式 → 保留原样
- 数据管线的 "Text → ID → Vector" 三步骤，跟图像处理的 "像素 → 特征 → 张量" 本质相通

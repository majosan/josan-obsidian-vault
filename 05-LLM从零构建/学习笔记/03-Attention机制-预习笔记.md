## 0. 为什么 Attention 是全书的心脏

Ch2 我们把每个 token 变成了一个 768 维向量（查表相加得到）。
但此时每个 token 的向量是**孤立的**——"它"和"银行"这两个词，向量完全不知道彼此。

**Attention 干的事：让每个 token 去看一眼上下文里的其他 token，把相关信息"吸收"进自己的向量里。**

```
Ch2 之后：  [银行]的向量 = 词义 + 位置     （孤立）
Ch3 之后：  [银行]的向量 = 词义 + 位置 + 吸收了上下文中"它"的信息
             ↑ 这就是"理解上下文"
```

> 类比：查表是"查字典"（词义固定），Attention 是"看上下文"（词义随语境变化）。

## 1. QKV 三件套（本ch最大概念门槛）

每个 token 的输入向量，会被三个可学习权重矩阵投影成三个新向量：

| 名称    | 全称        | 类比           | 作用             |
| ----- | --------- | ------------ | -------------- |
| **Q** | Query（查询） | 你在搜索引擎输入的关键词 | "我在找什么信息？"     |
| **K** | Key（键）    | 网页的标题/索引     | "我有什么信息可被找到？"  |
| **V** | Value（值）  | 网页的实际内容      | "被找到后，给出什么内容？" |

```python
# 伪代码（真实代码里是矩阵乘法）
Q = 输入向量 @ W_q    # W_q: 768×768，可学习
K = 输入向量 @ W_k    # W_k: 768×768，可学习
V = 输入向量 @ W_v    # W_v: 768×768，可学习
```

### ⚠️ 呼应 Ch2 的关键点
**W_q / W_k / W_v 也是可学习参数！** 和 embedding 表一样，随机初始化 + 训练学出来。
你已经在 Ch2 建立了"哪些是参数、哪些是计算"的敏感度，这里直接套用：
- 参数（训练学）：embedding 表、位置表、W_q、W_k、W_v
- 计算（运行时做）：查表、矩阵乘法、softmax、加权求和

## 2. 自注意力计算流程（4 步）

对序列中**每一个 token**，做同样的事：

```
第1步  投影：    输入向量 → Q, K, V（三个 768 维向量）
第2步  算相似度： 当前token的Q 与 所有token的K 做点积 → 得到一串分数
                 （分数越高 = 越相关 = 越值得关注）
第3步  归一化：   分数 ÷ √d_k → softmax → 变成"注意力权重"（和为1）
第4步  加权求和： 用权重对所有token的V 加权平均 → 得到新向量
```

**结果**：每个 token 的新向量 = 上下文中所有 token 信息的加权混合，
权重由"相关性"决定——相关的内容占比大，无关的占比小。

---

## 3. 两个关键细节

### 3.1 为什么要除以 √d_k（缩放因子）

- 向量维度越大，点积结果越大（768 维相加，数值容易膨胀）
- 数值太大会把 softmax 推向极端（一个 1 其余 0），梯度消失
- 除以 √d_k 把数值拉回稳定范围 → 训练更稳

### 3.2 因果掩码（Causal Mask）—— GPT 是 decoder-only

- 语言模型只能看**左边**（已生成的词），不能看右边（未来的词）
- 否则就"作弊"了：预测下一个词时偷看了答案
- 实现：计算相似度后，把"右边"的分数设成 -∞，softmax 后权重为 0
- 这就是你以后会看到的 `masked_fill` 或 `attn_mask` 的由来

```
    我  打  你          （矩阵中 行=查询位置，列=可看的键位置）
我   ✅  ❌  ❌
打   ✅  ✅  ❌         ❌ = 未来位置，被掩码遮住
你   ✅  ✅  ✅
```

## 4. 多头注意力（Multi-Head Attention）

- 不是只做一次 Attention，而是**并行做多次**（GPT-2 小模型 = 12 个头）
- 每个头有自己的 W_q/W_k/W_v（12 组！）
- **每个头关注不同类型的关联**：
  - 有的头关注"语法关系"（主谓宾）
  - 有的头关注"指代关系"（它 → 银行）
  - 有的头关注"位置距离"
- 最后把 12 个头的输出**拼接**再投影回 768 维

> 类比：一个专家看不全，12 个专家从不同角度各看一遍，汇总意见。

---

## 5. Ch2 → Ch3 的桥梁（为什么位置编码那么重要）

**Attention 本身是"无序"的**——它只是加权求和，不关心 token 顺序。
顺序信息完全靠 Ch2 注入的 Position Embedding 提供。
所以 Ch2 的位置编码不是可选项，是 Attention 能理解语序的前提。

> 你 Ch2 里学的"绝对位置"在这里兑现价值了。

## 一、LLM 三阶段的"全景地图"

先看这张大图，然后我们往下逐个拆解：

```
原始文本（几千亿 tokens，网络爬取）
        │
        ▼
┌─────────────────────────────────────┐
│    【阶段一：Building 模型搭建】       │
│                                      │
│  文本 → Tokenizer(BPE) → Token ID    │
│                                      │
│  Token ID → Embedding(向量化)         │
│           ↓                          │
│  Positional Encoding(加位置信息)      │
│           ↓                          │
│  Transformer Block × N(核心算力)      │
│    ┌─ Multi-Head Attention(注意力)    │
│    └─ Feed-Forward(前馈网络)           │
│           ↓                          │
│  Output → 概率分布(下一个词)           │
└─────────────────────────────────────┘
        │ 初始权重（随机）
        ▼
┌─────────────────────────────────────┐
│    【阶段二：Pre-training 预训练】     │
│                                      │
│  目标：预测下一个词（Next Token）       │
│  数据：互联网级海量文本                  │
│  方法：梯度下降 × 损失函数(CrossEntropy)│
│  结果：基础模型（通用能力）              │
│  (GPT-4/LLaMA/Qwen 等)               │
└─────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────┐
│    【阶段三：Fine-tuning 微调】        │
│                                      │
│  ┌─ 分类微调（分析情感/类别）          │
│  ├─ 指令微调（SFT, 对话能力）          │
│  ├─ RLHF（人类偏好对齐）               │
│  └─ LoRA（低成本微调，不改所有参数）    │
│                                      │
│  结果：专才模型（如 DeepSeek 助手）     │
└─────────────────────────────────────┘
```

## 二、逐个概念深度拆解

### 1️⃣ Embedding（嵌入层）— 把"词"变成"向量"

**一句话**：电脑不认识中文，只认识数字。Embedding 就是把每个词变成一串数字（向量）。

**为什么需要？**

```
"猫"   →  [0.23, 0.87, -0.14, 0.55, ...]   ← 256 维向量
"狗"   →  [0.31, 0.79, -0.08, 0.61, ...]   ← 同维度
"冰箱" →  [-0.45, 0.12, 0.67, -0.33, ...]  ← 同维度

猫和狗的向量"距离近"（语义相近）
猫和冰箱的向量"距离远"（语义远）
```

**关键理解**：
- **词表大小**：比如 GPT-2 是 50,257 个词
- **嵌入维度**：GPT-2 Small 是 768 维，GPT-3 是 12,288 维
- **本质**：就是一个巨大的**查找表**（Lookup Table），50,257×768 = 约 3800 万个参数
- **参数可学习**：这些数字不是人写的，是模型训练过程中自动学出来的

**类比**：
> 想象一个 50,257 行、768 列的 Excel 表格。查"猫"这个 ID → 读出那一行 768 个数。这 768 个数就是"猫"在模型眼中的"含义编码"。

**和 One-Hot 编码的区别**：
- One-hot：50,257 个位置，只有 1 位是 1，其余是 0（极度稀疏，浪费）
- Embedding：压缩成 768 个实数（稠密，高效，表达力强）

**跟文本分类的关系**：
> Embedding 把"这部电影很好看"编码成一组向量 → 模型从这个向量里提取"情感特征"→ 判断是正面还是负面。

### 2️⃣ Positional Encoding（位置编码）— 告诉模型"词的顺序"

**问题**：给 Embedding 层输入的是 `[我, 爱, 你]`，但 Embedding 本身**没有顺序概念**。`[你, 爱, 我]` 的 Embedding 跟上面一模一样。

**解决方案**：给每个位置加一个"位置码"。

```
"我" 的 Embedding + (位置1的编码) → [0.28, 0.91, ...]
"爱" 的 Embedding + (位置2的编码) → [0.33, 0.85, ...]
"你" 的 Embedding + (位置3的编码) → [0.21, 0.77, ...]
```

**两种常见方案**：
1. **绝对位置编码**（GPT 用的）：位置 1 一个固定向量，位置 2 一个... 类似学出来的位置表
2. **RoPE（旋转位置编码）**（LLaMA/Qwen 用的）：更高级，能处理更长的上下文，续写时位置越远注意越弱

**为什么重要**：没有位置编码，模型看"我打你"和"你打我"完全一样——那就完蛋了。

### 3️⃣ Multi-Head Attention（多头注意力）— 模型的核心算力

**这是整个 Transformer 最重要的机制。**

#### 先理解 Attention：
```
Query:   "我"（我在找什么？）
Key:     "爱"、"你"（你们是什么？）
Value:   "爱"、"你"（你们有什么信息？）

"我" 跟 "爱" 的匹配度 = 0.92  ← 高度相关
"我" 跟 "你" 的匹配度 = 0.34  ← 相关度低

最终结果 = 0.92 × "爱" + 0.34 × "你"
```

**本质**：**根据 Query 去 Key 里找最相关的信息，加权提取 Value**。

#### 为什么需要多头？

一个头只能关注一种关系：

```
头1（语法关系）："它" → "猫"（代词指代谁？）
头2（语义关系）："跑" → "快"（动词的修饰语？）
头3（距离关系）："过去" → "三天"（时间远近？）
头4（实体关系）："马斯克" → "特斯拉"（人跟公司？）
...
```

**多头注意力 = 多个 Head 并行各自关注不同方面**，然后拼接起来。

**GPT-2 Small 配置**：
- 嵌入维度：768
- Head 数：12（12 种关系视角）
- 每个 Head 的维度：768 ÷ 12 = 64

**类比**：
> 12 个专家各看一遍文本：
> - 专家A 看语法关系
> - 专家B 看情感
> - 专家C 看逻辑
> - ...
> 12 个人看完了，1 张纸汇总给老板。

**关键参数关系**：
```
嵌入维度(768) = Head数(12) × 每个Head维度(64)
```

### 4️⃣ Loss Function（损失函数）+ Gradient Descent（梯度下降）

这部分直接来自深度神经网络，不是 Transformer 发明的。

#### Loss Function — 衡量"错了多少"
```
模型预测：我打你 → 输出概率：[我0.1, 爱0.8, 鱼0.7, 你0.3]
正确答案：         [我,    爱,    你]

模型猜对了"爱"（概率0.8还行）
但下一位置模型猜"鱼"而不是"你"

Loss = CrossEntropy(预测, 正确答案) = 2.3  ← 数值越大错得越离谱
目标：把 Loss 降到接近 0
```

**CrossEntropy（交叉熵损失）是 GPT 预训练的标准损失函数**。

本质：**模型预测的概率分布跟真实分布有多像？越不像，loss 越大。**

#### Gradient Descent — 怎么"调整参数"

```
想象你站在一座山上（Loss 曲面），目标是走到最低谷。

你往前走一步 → 地势是上升还是下降？
               ↓
梯度 = 当前位置最陡的下降方向
               ↓
参数 = 往那个方向迈一小步（学习率控制步长）
               ↓
重复几万亿次 → 走到最低谷（Loss 最小化）

词嵌入的每个数字、注意力权重、前馈网络的参数 = 山上的坐标
```

**反向传播（Backpropagation）**：从最后一层往第一层，逐层算出每个参数的梯度。

**学习率（Learning Rate）**：步长。太大→跳过山谷，太小→永远走不到。

**GPT-3 规模的直观感**：
- 参数：1750 亿个
- Loss 函数就是这 1750 亿维空间的一个超曲面
- 梯度下降就是在这个高维空间找最低点

### 5️⃣ 嵌入维度 — 为什么是 768 不是 1000？

不是随便选的，是**工程权衡**：

```
维度越高 → 表达力越强（能编码更复杂的语义）
          但参数越多（计算量平方增长）
          需要更多数据（否则过拟合）

维度越低 → 计算快、省显存
          但表达能力受限

GPT 系列的选择：
  GPT-1:   768
  GPT-2 M: 1024
  GPT-2 XL: 1600
  GPT-3:   12288
  LLaMA-7B: 4096
```

**"嵌入维度 = 768"意味着每个词在模型眼中是 768 个数字一起描述的**。

---

### 6️⃣ 多头注意力的数量 — 为什么是 12 不是 5？

也是工程权衡：

```
Head 太少 → 能关注的关系类型少，表达能力差
Head 太多 → 每个 Head 参数太少，学不出有意义的模式

经验法则：嵌入维度 / Head数 = 每个Head的维度，这个值通常取 64 或 128
```

所以 GPT-2 Small 配 12 个头：768 ÷ 12 = 64 ✓

**类比**：一个团队有 12 个领域专家比 5 个好，但如果搞 100 个，每个专家分到的资源太少，也干不了事。

### 7️⃣ 模型搭建里提到的"借鉴深度神经网络" — 其他架构

Transformer 不是凭空冒出来的，它借鉴了：

| 前身技术 | 被 Transformer 吸收的部分 |
|----------|--------------------------|
| **RNN/LSTM**（循环神经网络） | 序列建模的概念（但 Transformer 用注意力替代了递归） |
| **CNN**（卷积神经网络） | 多层堆叠的设计思路（Transformer Block 叠 N 层） |
| **残差连接（ResNet）** | 每个 Transformer Block 的输入直接加到输出上（解决深层网络退化） |
| **层归一化（LayerNorm）** | 让每层输出保持稳定分布（加速训练） |
| **词嵌入（Word2Vec/GloVe）** | 文本向量化的起点（但 Transformer 的嵌入跟模型一起训练） |

**关键**：Transformer 的革命性贡献是**抛弃了 RNN 的递归结构**，用纯注意力机制做序列建模——这带来了并行计算和长距离依赖的优势。

### 8️⃣ RAG（检索增强生成）— 给 LLM 外挂知识库

**RAG 不是模型架构，是一种"外部知识注入"策略。**

```
用户问："我们公司的报销政策是什么？"

┌─────────────────────┐
│  ① 搜索知识库       │ ← 向量数据库（把文档向量化存储）
│  "报销 政策 流程"    │
└─────────────────────┘
        │
        ▼ 找到相关文档片段
┌─────────────────────┐
│  ② LLM 生成回答     │
│  "根据公司政策...    │ ← 把搜到的文档片段拼进 Prompt
│   出差住宿报销上限    │
│   为每天500元..."    │
└─────────────────────┘
```

**为什么需要 RAG**：
- LLM 的训练数据有截止日期（不知道最新信息）
- LLM 不知道你公司的内部文档
- LLM 会"幻觉"（编造答案），RAG 提供事实锚点
- 比微调便宜得多（不用训练模型，只建向量数据库）

**跟我们项目的关系**：
> 未来的 AI 化学实验室可以把**实验 SOP、试剂安全手册、设备操作指南**做成 RAG 知识库——LLM 回答实验问题时自动检索，比重新训练一个模型便宜一万倍。

**RAG vs 微调**：

| | RAG | 微调 |
|--|-----|------|
| 成本 | 低（只建数据库） | 高（需要 GPU 训练） |
| 实时性 | 秒级更新 | 需要重新训练 |
| 知识广度 | 跟数据库一样大 | 受模型容量的限制 |
| 适合场景 | 知识查询、事实问答 | 行为对齐、风格迁移、新技能 |

## 三、这些概念如何串起来？

**完整的 GPT 单次推理流程**（你理解了这张图就懂了 80%）：

```
输入："我爱"
        │
        ▼
① Tokenizer（BPE）→  [我→123, 爱→456]
        │
        ▼
② Embedding →  [[0.2, 0.8, ...], [0.5, 0.3, ...]]  ← 2×768 矩阵
        │
        ▼
③ 加位置编码  →  [位置1的编码, 位置2的编码]
        │
        ▼
④ Multi-Head Attention（12 个头各自看一遍）
   →  输出：2×768（每个位置的"上下文感知的表示"）
        │
        ▼
⑤ Feed-Forward 层（MLP，全连接网络）
   →  输出：2×768
        │
        ▼
⑥ LayerNorm + 残差连接（防止退化）
        │
        ▼
⑦ 重复 ④⑤⑥ × N 层（GPT-2 Small = 12 层）
        │
        ▼
⑧ 最后一层线性映射 + Softmax
   →  输出：[猫 0.01, 狗 0.02, 你 0.85, 吃 0.03, ...]
        │
        ▼
⑨ 取概率最高的"你" → 输出下一个词！
```

**预训练时**，比较 ⑧ 的输出和正确答案，算 Loss → 梯度下降 → 更新所有参数。

## 四、快速概念速查表

| 概念 | 一句话 | 跟你的项目的联系 |
|------|--------|-----------------|
| **Embedding** | 把词变成一串数字 | 触觉数据也可以做"触觉嵌入" |
| **Positional Encoding** | 告诉模型词的顺序 | 光谱序列需要位置编码理解时间顺序 |
| **Multi-Head Attention** | 多个视角并行理解文本 | VLA 的 cross-attention 也是多头结构 |
| **Head 数** | 并行关注几种关系 | 你的触觉数据可能需要定制"触觉头" |
| **Embedding 维度** | 每个词用多少数字描述 | 越大越好但成本越高 |
| **Loss Function** | 衡量模型错多少 | 每个 ML 项目第一步就是设计 Loss |
| **Gradient Descent** | 一步步调整参数走向最优 | 所有训练的底层引擎 |
| **CrossEntropy** | 分类问题的标准 Loss | 文本分类微调用这个 |
| **学习率** | 参数调整的步长 | 太大震荡，太小跑不动 |
| **残差连接** | 跳过中间层直接加输入 | 深层网络的救命稻草 |
| **LayerNorm** | 让数据分布稳定 | 加速训练、防止梯度爆炸 |
| **RAG** | 外挂知识库给 LLM 查 | 化学实验室的 SOP 知识库 |
| **LoRA** | 微调不改全部权重 | 微调触觉编码器的首选 |
| **RLHF** | 人类反馈训练偏好 | 让模型说"人话" |

# 智能床垫压力监测垫系统 · 功能需求（V1.0）

> **系统定义**：面向**物业 / 养老机构**的柔性压力监测床垫系统。自动识别**坠床风险、离床、久卧不动**等异常，推送告警给护理人员与家属，并提供数据报表辅助护理决策。
>
> **架构口径（本版关键变化）**：**去掉 PC 网关**，采集板加装 **WiFi 模组**，实现 **手机端（小程序/后台）→ 云端 → 设备端（床垫）** 直连。
>
> **目标**：MVP = **单床位 + 多床位真实演示**（用于市场推广获取订单）；商业化 = **多机构 SaaS 化部署，支持百床位规模**。

## 0. 本版相对 V0.1/V0.2 的变化

| 项 | V0.1 / V0.2（PC 网关） | **V1.0（WiFi 直连）** |
|---|---|---|
| 设备接入 | PC 读串口 → PC 提特征 → POST | **采集板 + WiFi 模组直连云端** |
| 链路是否依赖 PC | **是（PC 常开）** | **否（PC 仅调试）** |
| 配网 | 无（降级为后台绑定） | **真配网：小程序 BLE / SoftAP 配网** |
| 事件判定 | 云端统一判定为主 | **边缘 + 云端双层**（设备可本地兜底） |
| 断网 | PC 端 sqlite 补传 | **设备端本地缓存 ≥ 24h，恢复续传** |
| 设备管理 | 无 | **OTA、自检、指示灯、生命周期、一机一密** |
| 上行数据 | 特征包（含 8×8 缩略图） | 特征包 + **事件包**（缩略图按需降频） |
| 适用范围 | 单机构 Demo | **多租户 SaaS（百床级）** |
| 云端/小程序 | 同 | **沿用，基本零改动**（协议一次做对） |

> **结论**：旧版 v0.1/v0.2 是"最快跑通 Demo"的历史产物，已完成演示验证（后端数据链路已跑通，仅差小程序端）。**V1.0 是产品化主线**，小程序/后台可大量复用。

## 1. 范围与目标

### 1.1 目标
| 阶段 | 目标 | 成功判据 |
|---|---|---|
| **MVP** | 单床位真实演示 + 多床位真实演示，用于市场推广获取订单 | 现场演示"上床→离床→告警→处理"全链路一次成功 |
| **商业化** | 多机构 SaaS 化部署，百床位规模 | 单机构 ≥ 200 床稳定运行；新机构开通 ≤ 1 天 |

### 1.2 本轮做
- 设备端：WiFi 直连、配网、边缘判定、断网缓存、OTA
- 云端：设备管理、数据存储、规则告警、多租户、通知推送、聚合报表、开放 API
- 应用端：护理端小程序（核心）、家属端小程序、机构后台 Web、物业/社区看板、（大屏）
- 数据与算法：热力图、姿态、离床/坠床风险/久卧、睡眠/体动、体重估算（迭代）

### 1.3 本轮不做（明确边界）
- 医疗诊断类功能（心率/血氧/呼吸暂停诊断等）——传感器能力外，且涉医疗宣称
- 视频监控（隐私红线，仅压力感知）
- 同床多人识别
- 独立 App（走微信小程序；商业化再评估）
- 呼叫中心/坐席话务系统（可对接第三方）

## 2. 系统架构（V1.0）

### 2.1 三层架构

```
┌──────────────────────── 设备端（床垫 + 采集板 + WiFi 模组）────────────────────────┐
│  32×32 柔性压力阵列 → 扫描采集 → MCU 预处理 → 边缘事件判定                        │
│        │                                                                          │
│        ├─ 本地指示灯 / 蜂鸣（告警提示，可选）                                      │
│        ├─ 本地缓存（断网 ≥ 24h 事件与状态）→ 恢复续传                              │
│        └─ WiFi 模组（2.4GHz）── TLS ──▶  MQTT/HTTPS 上行云端                        │
└───────────────────────────────────────┬──────────────────────────────────────────┘
                                        ▼
┌───────────────────────────── 云端（平台）─────────────────────────────────────────┐
│  接入网关(MQTT/HTTPS) → 设备管理/设备影子 → 存储 → 规则引擎 → 告警中心               │
│       │                                    │                                     │
│       ├─ 通知服务（订阅消息/短信/语音外呼/Webhook）                                │
│       ├─ 聚合与报表引擎（定时任务）                                                │
│       ├─ 多租户与权限（RBAC）                                                      │
│       └─ 开放 API                                                                  │
└───────────────────────────────────────┬──────────────────────────────────────────┘
                                        ▼
┌───────────────────────────── 应用端 ──────────────────────────────────────────────┐
│  微信小程序·护理端（核心）  微信小程序·家属端  机构后台 Web  物业/社区看板  大屏    │
└───────────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 时钟与配网
- **配网**：手机小程序 → BLE / SoftAP → 下发 WiFi SSID/密码 + 设备绑定 token → 设备连网并回执。
- **时钟**：设备 NTP 对时；离线期间用本地时钟，续传时带 `deviceTs` 与 `cloudTs`，云端以设备时间为事件序依据。

## 3. 功能需求清单

> 优先级：**P0 = MVP 必须** ｜ **P1 = MVP 一起做/首个商业化** ｜ **P2 = 商业化迭代** ｜ **P3 = 远期**
> 每条含 **验收标准（AC）**，作为开发与验收依据。

### A. 设备端（床垫 + 采集板 + WiFi）

#### A1 压力采集与预处理 · **P0**
- 32×32 阵列采集，采样 ≥ 15Hz。
- 预处理：滤噪、基线漂移校正、坏点/断线补偿。
- 生成特征：总压力、重心坐标、峰值、`edgePct`（边沿占比）、8×8 缩略图、在床判定。
- **AC**：静态基准下，压力值漂移 ≤ 5%/8h；特征计算耗时 ≤ 20ms/帧。

#### A2 边缘事件判定 · **P0**
- 设备本地判定：`离床`、`回床`、`坠床风险`、`久卧`、`翻身`。
- 与云端**双保险**：设备判定的即时事件（低延迟） + 云端规则复核（可配置、可调阈值）。
- **AC**：事件从发生到发出上行包 ≤ 3s（P95）。

#### A3 WiFi 配网 · **P0**
- 支持 **BLE 配网**（首选）与 **SoftAP 配网**（兜底）。
- 小程序内完成：扫码设备 ID → 输入 WiFi → 下发 → 设备回执成功/失败。
- 失败可重试并给出明确指引（密码错/信号弱/非 2.4G）。
- 支持**一键重置配网**（长按按钮）。
- **AC**：**单床配网 ≤ 3 分钟**，一次成功率 ≥ 90%。

#### A4 联网通信 · **P0**
- 协议：**MQTT over TLS（推荐）** 或 HTTPS；一机一密或证书鉴权。
- 心跳：默认 30s；上下行 QoS 分级（事件 QoS1，状态 QoS0）。
- **断网缓存**：本地环形/Flash 队列，**缓存 ≥ 24h** 事件；恢复后按 `seq` 补传，云端**幂等去重**。
- **AC**：断网 2h 后恢复，事件**零丢失**；重复率按 seq 去重为 0。

#### A5 设备管理与 OTA · **P0（基础）/ P1（OTA）**
- 上报：设备 ID、固件版本、电量、信号强度、在线状态、自检结果。
- **OTA**：差分/整包升级，**灰度分批**、断点续传、失败回滚（双分区）。
- 指示灯：配网中 / 已联网 / 断网 / 告警（颜色约定，另附文档）。
- **AC**：OTA 升级成功率 ≥ 98%；升级失败可回滚到可用版本。

#### A6 设备安全 · **P0**
- 一机一密（或一机一证书），密钥不可读。
- 固件签名校验；调试口量产关闭；防拆/防篡改（可选）。
- **AC**：伪造设备无法上行；固件非签名包拒绝刷入。

#### A7 供电与功耗 · **P1（有线）/ P2（电池版）**
- 有线版：DC/USB 常供电。
- 电池版：上报降频、深度休眠，**续航目标 ≥ 30 天**，低电量上报（L2 告警）。
- **AC**：电池版实测续航 ≥ 目标值 80%。

### B. 云端平台

#### B1 设备接入与设备管理 · **P0**
- 设备注册/激活/绑定/解绑/停用；设备生命周期状态机。
- **设备影子**：最新状态（在线、在床、电量、固件版本、信号）。
- **AC**：单平台支持 ≥ 5000 设备在线；设备列表可筛选导出。

#### B2 数据存储 · **P0**
- **三层存储**：状态**覆盖写** + 事件**追加** + 统计**定时聚合**（严禁存原始 15Hz 帧）。
- 集合/表：`devices`、`device_status`、`events`、`alerts`、`beds`、`rooms`、`elders`、`users`、`tenants`、`alert_rules`、`stats_hourly`、`stats_daily`、`audit_logs`。
- **AC**：单床日写入量 ≤ 2 万条；查询最新状态 ≤ 300ms。

#### B3 规则引擎与告警 · **P0**
- 规则：离床超时、久卧、翻身、**坠床风险**、设备离线、低电量。
- 阈值与**生效时段**支持 **全局 / 机构 / 床位** 三级配置，床位覆盖上级。
- 告警**事件窗口去重**、**静默期**、**免打扰时段**。
- **AC**：规则改动 1 分钟内生效；重复告警去重有效。

#### B4 通知推送 · **P0（订阅消息）/ P1（短信/语音）**
- 渠道：小程序消息中心（兜底）、微信订阅消息、短信、语音外呼、Webhook。
- **分级与升级**（见场景文档 §6）：L3 未接单 5min → 主管；10min → 管理员+家属。
- 通知对象可配置（值班组/个人/家属）。
- **AC**：L3 告警从产生到手机收到 ≤ 10s（P95）。

#### B5 聚合与报表引擎 · **P0（基础）/ P1（导出）**
- 定时任务：小时/日聚合（在床时长、离床次数、翻身次数、告警数与响应时长）。
- 报表：日报/周报/月报；趋势图、事件分布、依从率。
- 导出：Excel/CSV/PDF。
- **AC**：日报自动生成且数据可与原始事件对账。

#### B6 账号 · 权限 · 多租户 · **P0（权限）/ P1（多租户）**
- RBAC 角色（见场景文档 §4.2）；**租户数据强隔离**。
- 登录：小程序微信授权 / 后台账号密码 + 可选短信验证码。
- **AC**：跨租户越权访问被拒绝（含 API 层）。

#### B7 开放 API 与集成 · **P2**
- 提供 REST API / Webhook：状态查询、告警推送、档案同步。
- 对接对象：机构 HIS/养老平台、物业系统、呼叫中心、监管平台。
- **AC**：提供 API 文档 + 沙箱；Webhook 支持重试与签名校验。

#### B8 平台运营与运维后台 · **P1**
- 设备监控大屏（在线率、告警数、异常设备）、远程诊断、日志查询。
- OTA 发布管理、租户开通、工单。
- **AC**：可远程定位单设备故障原因。

#### B9 安全与合规 · **P0**
- 传输 TLS1.2+；敏感字段加密存储；最小权限；**审计日志**。
- 个人信息保护：**知情同意**流程、数据脱敏、留存策略、境内存储。
- 文案合规：对外用"**预警/风险/提醒**"，**禁用**"报警/监护/诊断"等医疗宣称。
- **AC**：通过内部安全自查表；隐私政策与同意书齐备。

## 5. 非功能需求（NFR）

| 类别 | 指标 |
|---|---|
| **实时性** | 事件→通知 ≤ 10s（P95）；看板刷新 ≤ 5s；热力图 ≤ 3s |
| **准确性** | 在床判定准确率 ≥ 99%；离床漏报 ≤ 1%/天；误报 ≤ 2 次/床/天 |
| **可靠性** | 云端可用性 ≥ 99.9%；断网缓存 ≥ 24h 且零丢失 |
| **容量** | 单机构 ≥ 200 床；平台 ≥ 5000 设备；单床日写入 ≤ 2 万条 |
| **安全** | TLS1.2+、一机一密、RBAC 最小权限、审计日志、防伪造 |
| **合规** | 个人信息保护法；知情同意；数据境内；**不医疗宣称** |
| **功耗** | 有线常供；电池版续航 ≥ 30 天 |
| **可维护** | 远程诊断、OTA、日志可查；单设备故障可定位 |
| **成本** | 单床月云成本目标 ≤ 设定值（按状态 5s 覆盖写 + 事件追加估算） |
| **兼容** | 2.4GHz WiFi；小程序兼容主流微信版本；后台兼容主流浏览器 |
| **可扩展** | 多租户、可插拔通知渠道、开放 API |

## 6. 关键数据模型（要点）

| 集合 | 键 | 写入方式 | 说明 |
|---|---|---|---|
| `tenants` | tenantId | 少 | 机构/物业项目 |
| `devices` | deviceId | 少 | deviceKeyHash、firmware、bindings、lastTs |
| `device_status` | deviceId | **覆盖写** | inBed/centroid/peak/edgePct/thumb/battery/rssi/online + 状态机时间戳 |
| `events` | eventId | 追加 | leave_bed/return_bed/long_lie/turn/fall_risk/offline |
| `alerts` | alertId | 追加 | type/level/status(待接单/处理中/已处理/已归档)/handler/notes |
| `beds` / `rooms` | bedId/roomId | 少 | 层级与绑定 |
| `elders` | elderId | 少 | 档案 + 同意书状态 |
| `users` | openid/userId | 少 | 角色、关联床位/机构 |
| `alert_rules` | ruleId | 少 | 全局/机构/床位三级 |
| `stats_hourly`/`stats_daily` | bedId+period | 定时聚合 | 报表数据 |

## 7. 接口需求（概览）

1. **设备上行（MQTT/HTTPS）**
   - 状态包：`deviceId, seq, ts, inBed, total, centroid, peak, edgePct, thumb, battery, rssi, fw`
   - 事件包：`deviceId, seq, ts, event(leave_bed/return_bed/long_lie/turn/fall_risk), payload`
   - 鉴权：一机一密 / 证书。
2. **云端下行**
   - 规则与阈值下发、OTA 指令、重启/自检指令、配网确认。
3. **应用端 API**
   - 状态查询、事件/告警列表、告警处理、档案与床位管理、报表、通知配置。
4. **开放 API / Webhook**（P2）：告警回调、状态回调、档案同步。

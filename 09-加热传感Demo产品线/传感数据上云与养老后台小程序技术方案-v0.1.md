# 传感布数据上云 + 养老后台/小程序 技术方案（V0.1）

> **用途**：32×32 传感布 → PC 网关（Python）→ 微信云开发 → 后台管理系统 + 小程序，全链路技术方案。
> **场景**：第一锚点 = 养老（压力传感床垫 / 轮椅垫），后台看板 + 家属端/护工端小程序。

---

## 0. 本次已定决策

| 项 | 决策 | 说明 |
|---|---|---|
| 上行方案 | **PC 当串口网关（方案 A）** | 硬件零改动，最快跑通 |
| 云平台 | **微信云开发** | 免域名备案，小程序原生直连 |
| PC 端可视化 | **Python（保留现有）** | 不重构，只加"转发"模块 |
| 串口波特率 | **1,000,000 bps** | ≈100 KB/s，15Hz×1024B=15.4KB/s，余量 6× |

**关键前提（必须记住）**：微信小程序**只能访问公网 HTTPS 域名**，不能连局域网 IP / 裸 TCP。
→ 所以 **PC 只做「串口网关」，业务后端放云开发**，小程序连云开发，不连 PC。

## 3. PC 端网关改造（Python）

### 3.1 线程/进程结构（三条线，互不阻塞）

| 线程 | 职责 | 原则 |
|---|---|---|
| **① 读串口** | 收帧 → 丢进环形缓冲 | **只读不处理，绝不阻塞** |
| **② 本地可视化** | 从缓冲取最新帧画图 | 保留现有代码 |
| **③ 上云转发** | 取最新帧 → 特征提取 → 降频 → POST | 失败静默重试，不拖累 ①② |

> **铁律**：网络发送**不能**在串口读取线程里做。网络一卡，整个采集就死。

### 3.2 环形缓冲（防卡死核心）

```python
from collections import deque
frame_q = deque(maxlen=200)   # 满则自动丢最老帧
```
- 读线程 `frame_q.append(frame)`
- 可视化线程读 `frame_q[-1]`（最新帧）
- 转发线程也取 `frame_q[-1]`
- **满了丢老的，绝不反压** —— 采集永远是"真"的，只有展示/上云可能丢帧

### 3.3 降频策略（重要，直接决定云端成本）

| 数据 | 频率 | 说明 |
|---|---|---|
| 本地可视化 | **15 Hz** | 给人看，不能降 |
| 上云·状态 | **默认 0.2 Hz（每 5s）** | 家属端看"在床/离床"足够 |
| 上云·事件 | **事件触发立刻发** | 离床、久卧、翻身、设备离线 |
| 上云·聚合 | 云函数定时（每小时/每天） | 生成报表数据 |

### 3.4 特征提取（关键！别传原始 1024 点）

**传原始数据上云 = 烧钱**。32×32 原始点 → 精简成"特征包"：

| 特征 | 计算 | 字节 |
|---|---|---|
| 压力分布缩略图 | 32×32 下采样到 **8×8**（块均值/最大值） | 64 B |
| 总压力 | 所有点求和 | 4 B |
| 压力重心 (x,y) | 加权质心 | 8 B |
| 峰值压力 | max | 2 B |
| 在床判定 | 总压力 > 阈值 | 1 B |
| 时间戳 / 设备ID | | 12 B |
| **合计** | | **≈90 B**（vs 原来 1024 B，省 11×） |

> 原始 1024 点数据：**只留在 PC 本地**（可存本地文件/sqlite 供回溯），**不上云**。云端只存特征与事件。

### 3.5 断线容错

- POST 失败 → **静默跳过**（本地可视化不受影响）
- 事件类数据（离床告警）→ 本地落盘 **sqlite/文件队列**，恢复后**补传**
- 超时设 3s，重试退避，避免堆积线程

### 3.6 Python 代码骨架（可直接改造）

```python
import serial, time, threading, requests
from collections import deque

SERIAL_PORT = "COM3"
BAUD        = 1_000_000
CLOUD_URL   = "https://<云开发HTTP访问地址>/ingest"
DEVICE_KEY  = "<自定义鉴权密钥>"
DEVICE_ID   = "BED-0001"
UP_INTERVAL = 5.0          # 状态上云间隔（秒）
POINTS      = 32
IN_BED_TH   = 500          # 在床判定阈值（需标定）

ser     = serial.Serial(SERIAL_PORT, BAUD, timeout=0.1)
frame_q = deque(maxlen=200)
stop    = threading.Event()

# ---------- ① 读串口 ----------
def reader():
    buf = b""
    while not stop.is_set():
        data = ser.read(4096)
        if not data:
            continue
        buf += data
        for frame in parse_frames(buf):      # TODO: 换成你的协议解析
            frame_q.append(frame)            # 满则丢最老

# ---------- ② 上云转发 ----------
def extract(frame):                       # 32x32 -> 特征包
    thumb  = downsample_8x8(frame)        # TODO: 8x8 下采样
    total  = sum(frame)
    cx, cy = centroid(frame)              # TODO: 加权质心
    return {
        "deviceId": DEVICE_ID, "ts": int(time.time() * 1000),
        "inBed": total > IN_BED_TH, "total": total,
        "centroid": [round(cx, 2), round(cy, 2)],
        "peak": max(frame), "thumb": thumb,
    }

def cloud_pusher():
    last = 0
    while not stop.is_set():
        now = time.time()
        if frame_q and now - last >= UP_INTERVAL:
            try:
                requests.post(CLOUD_URL, json=extract(frame_q[-1]),
                              headers={"X-Device-Key": DEVICE_KEY}, timeout=3)
                last = now
            except Exception:
                pass                      # 断网：跳过，不影响本地

threading.Thread(target=reader,       daemon=True).start()
threading.Thread(target=cloud_pusher, daemon=True).start()

# ---------- ③ 主线程：本地可视化（保留现有代码） ----------
visualize(frame_q)                        # 你现有代码，只需改成读 frame_q
```

> 改动量：现有可视化代码只需把"读串口"换成"读 `frame_q`"，其余逻辑不动。

## 4. 数据协议

### 4.1 串口帧（保持现状，不动）
- 波特率 1,000,000，格式沿用现有协议

### 4.2 上云数据包（精简特征包，JSON）

```json
{
  "deviceId": "BED-0001",
  "ts": 1757970000000,
  "inBed": true,
  "total": 3421,
  "centroid": [15.2, 18.7],
  "peak": 255,
```

- ⚠️ 现在单设备，但**协议字段必须先留**，否则后台多床位要返工

## 5. 微信云开发侧

### 5.1 用到的云开发能力

| 能力 | 用途 |
|---|---|
| **云函数** | `ingest`（接收）、`query`（查询）、`cron-stat`（定时聚合） |
| **云数据库** | 设备状态、事件、告警、用户、统计 |
| **HTTP 访问服务 / HTTP API** | 让 PC 网关（非小程序）能把数据 POST 进来 |
| **订阅消息** | 告警推送到微信 |
| 静态网站托管 | 后台管理系统（可选） |

> PC 怎么接云开发？两条路，**以云开发控制台实际开通方式为准**：
> ① **云函数配置 HTTP 访问服务** → PC 直接 POST 一个 URL（推荐，最简）
> ② **云开发 HTTP API** → 用 AppID+AppSecret 换 access_token 再调用（要自己管 token 刷新，2h 过期）
> 无论哪条，**都必须加自定义密钥 header** 做鉴权，别裸奔。

### 5.2 数据模型（集合设计）—— 成本敏感，重点

> ⚠️ **绝对不要**把 15Hz 原始帧写进云数据库，会写爆配额 + 烧钱。
> 按"**状态覆盖 + 事件追加 + 定时聚合**"三层来存：

| 集合 | 写入方式 | 内容 | 量级 |
|---|---|---|---|
| `device_status` | **覆盖写同一条**（每设备一条） | 最新 inBed/重心/缩略图/lastTs/online | 每设备 1 条 |
| `events` | 事件触发追加 | 离床、久卧、翻身、设备离线 | 每天几十条 |
| `alerts` | 告警触发追加 | 告警类型/级别/床位/状态(待处理/已处理) | 每天几条~几十条 |
| `beds` | 少量 | 床位、房间、机构、绑定设备、老人信息 | 静态 |
| `users` | 少量 | openid、角色（家属/护工/管理员）、关联床位 | 静态 |
| `stats_hourly` / `stats_daily` | **定时云函数**聚合写 | 在床时长、离床次数、翻身次数、告警数 | 每床每小时/天 1 条 |

**写入量对比**（单床）：
| 方案 | 写入/天 | 判断 |
|---|---|---|
| 原始帧 15Hz 直存 | 1,296,000 | ❌ 完全不可行 |
| 状态 5s 覆盖写 | 17,280 | ⚠️ 免费额度偏紧 |
| 状态 10s 覆盖写 | 8,640 | ✅ 可行 |
| 状态 5s + 事件 + 聚合 | ≈17k | 视套餐 |

> **建议**：状态上行间隔做成**配置项**（默认 5s，可调到 10s/30s）；免费额度以云开发控制台实时配额为准，多床位（≥5 张）建议直接上付费套餐。

### 5.3 云函数清单

| 云函数 | 触发 | 职责 |
|---|---|---|
| `ingest` | HTTP（PC POST） | 鉴权 → 校验 → 覆盖写 `device_status` → 规则判断 → 写 `events`/`alerts` → 发订阅消息 |
| `query` | 小程序 wx.cloud 调用 | 返回某床最新状态 / 事件列表 / 告警列表 |
| `alert-handle` | 小程序调用 | 护工处理告警（改状态） |
| `cron-stat` | 定时触发器（每小时/每天） | 聚合写 `stats_hourly`/`stats_daily` |

### 5.4 告警规则（放 `ingest` 里）

| 规则 | 判定 | 级别 |
|---|---|---|
| 离床 | `inBed` 由 true→false 且持续 > 15min（档位可配：15/30/60） | 中/高 |
| 久卧不动 | 重心变化 < 阈值 且持续 > 2h | 高（压疮风险） |
| 翻身提醒 | 距上次翻身 > 设定时长 | 中 |
| 坠床风险 | 重心持续偏床边沿 + 身体越界 | 高 |
| 设备离线 | `lastTs` 超时（如 > 2min 无上报） | 高 |

> 阈值全部做成**可配置**，不同机构/老人不一样。

### 5.5 订阅消息（告警推送）

- 用小程序**订阅消息**推送告警到家属/护工微信
- 限制：需用户**主动订阅**（一次性/长期），模板需申请
- 兜底：小程序内"消息中心"列表 + 后台看板轮询

## 8. 关键工程注意点（踩坑清单）

1. **降频 + 聚合是一切的底线** —— 原始帧别上云（见 §3.4 / §5.2）
2. **多设备 ID 现在就留字段** —— 后台多床位的前提
3. **网络与采集解耦** —— 环形缓冲 + 独立线程（见 §3.1/3.2）
4. **时钟同步** —— PC 用 NTP 对时，否则事件时间戳错乱
5. **在床阈值需标定** —— 不同床垫/老人体重差异大，阈值要可配 + 逐床校准
6. **云端鉴权** —— PC 上行加密钥 header，防伪造数据
7. **离线兜底** —— 事件本地落盘补传；云端 lastTs 超时判离线
8. **缩略图 vs 原始数据** —— 云端存 8×8，原始留本地

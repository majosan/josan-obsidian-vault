## 1. 缘起与目的

Josan 上传「织序智慧感知守护平台」材料（PDF 大纲 + 旧后台截图 + UI 参考图），启动云平台后台改造。

**核心目的（Josan 原话口径）**：
- 平台要**真正能售卖、运营**；
- 但**前期更大目的**是**用自家物业 + 楼盘为自己赋能**，跑出**真实的数据和数量**，实现"**公司对外售卖与融资**"；
- 因此新增了**看板**；后台要**好看、全面、符合定位**；
- **结合物业**，但**不能给物业增加太多工作与风险**，重点仍在**产品功能本身**。

## 5. 讨论细节与考量（重点）

### 5.1 看板：单独做 vs 放后台？
- 倾向**放后台、一套系统双视图**：数据同源、不重复维护；对外数字**可下钻**才硬（融资加分项）。
- 建议：一个「数据看板」页 = 顶部 KPI +「运营态势 / 经营增长」两 Tab（或折叠）；权限控制默认视图；支持**投屏/大屏**。
- 风险：不要把"实时告警(运营)"和"增长数字(投资)"堆一屏。

### 5.2 物业：现状是"没有系统"
- 物业目前**只有微信群 + 电话 + 口头**，**没有任何系统**。
- → **"对接物业系统"不现实**；强推系统 = 给物业加活、没人用、与目的相悖。
- → 定调：**物业 = 场景 / 背书 / 渠道**，不是操作员；**响应人 = 家属/亲友**，物业仅"值班兜底"（与 `功能需求 v1.1` 一致）。
- → 物业侧：告警进**微信/短信**；处理**一键/自动记录**；不做工单。

### 5.3 售后归属
- **归我方**（报修/维修/换货/记录）；物业可能**转达**。

### 5.4 统一称谓
- 因"卖设备 → 绑业主 → 使用者可能是老人也可能是猫狗"，需中性词。
- 选定 **「守护对象」**（与"守护平台"同源，人和宠物都适用）。

### 5.5 设备无定位 → 转手送人问题
- 结论：**基本没关系**——位置是**登记归属（台账）**，非实时定位。
- 配套：①配网**首次登记归属**；②**过户/换绑流程**；③**变更记录**；④（可选）用设备**公网 IP 做城市级"疑似迁移"提示**。
- 物业统计口径写明："**登记覆盖**"而非"实时所在"。
- **最终口径（Josan）**：我们**只负责第一次的台账登记**；后续他们自己更换/异地用**不管**；或他们**在小程序上重新绑定**，我们**只更新记录**。

### 5.6 心率 / 呼吸 / 宠物情绪
- 起因：Josan 在**矩侨工业**介绍/展会看到他们有这些功能（疑为**算法模拟**），想评估我们能否做。
- 技术判断（详见 §6）：
  - **呼吸**：可做"趋势"（非医疗）。
  - **心率**：15Hz 全帧压力难出真心率（BCG 需更高采样）；但可做"**估计版**"、加免责、可隐藏。
  - **宠物情绪**：无传感依据 → 改"活跃度/安静度"。

### 5.7 UI
- 参考图气质：深色图标侧栏 + 浅灰大留白 + 大圆角卡片 + 状态标记 + 有主次。
- Josan 细化要求：**银白色调、卡片式（不用胶囊）、大卡配小卡、有主视角大卡**。
- **不需要专门 skill**；正确做法 = 给 dhs 一份 **UI 大纲/范围**，把基调、布局、组件范围定死，具体样式由 dhs 实现。

## 6. 竞品调研：矩侨工业（威海矩侨）

> 官网 `https://jq-industries.com/`；产品资料页 `https://www.sensorexpert.com.cn/brand/23933.html`。

### 6.1 公司 / 产品线
- 柔性纤维传感器（**导电纤维在织造阶段即构成传感网络**）。
- **两条康养产品线**：
  - **VitalPad 生命体征监测垫**（家庭 / 独居老人，配小程序）
  - **Care+ 智护系列**（养老机构，**三端**：超级工作台 PC + 护理管理端 + 家属端）
  - 另有 Cloud 云护床垫、Care 安护监测垫、老年身体能力评估系统。
- 服务领域含：足底压力、床品舒适性/褥疮风险、汽车座椅、**柔性织物的心电采集**、运动评估。

### 6.2 ⚠️ 参数辨析（重要，已更正）
- 官网**首页「核心技术能力」**写：*"传感阵列最高支持 **16384 个采集点**与 **300Hz 动态采样**"*（企查查简介同）。
  → 这是**公司级"最高能力"**（机器人电子皮肤 / 高端测量设备），**不是床垫规格**。
- **床垫实际参数**（产品资料页明确）：
  - **Care 安护监测垫 = 160 个传感点**（活力老人/失智者）
  - **Care+ 智护监测垫 = 1024 个传感点**（失能/半失能）
  - **Cloud 云护床垫 = 1024 个传感点**
- **结论**：Josan 判断正确 —— **床垫就是 1024 点**（与展会一致）；我们规格书同为 **1024 点 / 15Hz**（见 `产品规格书 v1.0`）。

### 6.3 生命体征（心率）真相
- 官网原文：*"通过对**躯干部分的微动**监测，能够**推断**使用者的**呼吸和心率**"* —— 用词是「**推断**」。
- 其"**纤维电极**"服务领域含"**心电采集**"；但 Josan 确认该电极本质是**镀银纱线**（干电极），**与我们同源**，且与压力垫**是两条线**，**不太可能为床垫单独做纤维电极心电**。
- **判断**：矩侨床垫的"心率/呼吸"大概率是**算法估算/趋势**（特定条件下测算）+ 市场话术；**未取得医疗认证** → 对外只敢说"推断/趋势"。
- 其他功能：离床一秒警报、坠床潜在风险预警、坐起警报、**拍打呼救 SOS（≥85dB）**、Braden 压疮风险评估、电子翻身卡、护理超时提醒、睡眠报告、行为规律异常（如厕超时/长时间无活动/睡眠异常）、"脑卒中潜在风险预警"。

### 6.4 对我们的启示
- 我们可以**用同样口径**做"生命体征**趋势**"（呼吸/体动/睡姿 + **心率估计·非医疗**），**既"全面"又不担责**。
- **别照抄**"脑卒中预警/疾病预警"这类疾病宣称（红线）。

## 7. 技术 / 合规红线

1. **文案**：用「**预警 / 风险 / 提醒**」，**禁用**「报警 / 监护 / 诊断」。
2. **心率 / 体重 / 呼吸**：一律「**估计 / 趋势 · 非医疗**」，加免责；**不做医疗宣称**。
3. **不承诺**连续定位/轨迹；位置=登记归属。
4. **数据**：不外泄；原始帧不入云（沿用既有）。
5. **物业**：不增加其工作与责任；不替物业做决策。

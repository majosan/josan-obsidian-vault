# 智能床垫压力监测垫系统 · 功能需求（V1.1）

> **系统定义**：面向**物业 / 小区**的柔性压力监测床垫系统。自动识别**坠床风险、离床、久卧不动**等异常，推送告警给**家属亲友与物业值班人员**，并提供数据报表辅助照护决策。
>
> **架构口径**：**去掉 PC 网关**，采集板加装 **WiFi 模组**（**固件外包**），实现 **手机端 → 云端（IoT 平台）→ 设备端** 直连。
>
> **目标**：MVP = **单床位 + 多床位真实演示**（市场推广获单）；商业化 = **多机构/多小区 SaaS 化，百床位规模**。
> **试点**：**自有公司的小区物业**。

## 1. 范围与目标

### 1.1 目标
| 阶段 | 目标 | 成功判据 |
|---|---|---|
| **MVP** | 单床位真实演示 + 多床位真实演示，用于市场推广获取订单 | 现场演示"上床→离床→告警→处理"全链路一次成功 |
| **商业化** | 多机构/多小区 SaaS 化部署，百床位规模 | 单项目 ≥ 200 床稳定运行；新项目开通 ≤ 1 天 |

### 1.2 本轮做
- 设备端：WiFi 直连、配网、边缘判定、断网缓存、OTA（**固件外包**）
- 云端：**IoT 平台设备接入**、数据存储、规则告警、多租户、通知推送（**含短信**）、聚合报表、开放 API
- 应用端：**物业端小程序（值班）**、家属端小程序、项目后台 Web、物业看板、（大屏）
- 数据与算法：热力图、姿态、离床/坠床风险/久卧、睡眠/体动、体重估算（迭代）

### 1.3 本轮不做（明确边界）
- 医疗诊断类功能（心率/血氧/呼吸暂停诊断等）——传感器能力外，且涉医疗宣称
- 视频监控（隐私红线，仅压力感知）
- 同床多人识别
- 独立 App（走微信小程序；商业化再评估）
- 呼叫中心/坐席话务系统（可对接第三方）
- **养老机构专用功能**（护理排班、护理记录、医嘱联动等）——本版面向物业/居家，机构场景另开分支

## 2. 系统架构（V1.1）

### 2.1 三层架构

```
┌──────────────────── 设备端（床垫 + 采集板 + WiFi 模组，固件外包）────────────────────┐
│  32×32 柔性压力阵列 → 扫描采集 → MCU 预处理 → 边缘事件判定                          │
│        ├─ 本地指示灯 / 蜂鸣（可选）                                                 │
│        ├─ 本地缓存（断网 ≥ 24h）→ 恢复续传                                          │
│        └─ WiFi 模组（2.4GHz）── TLS ──▶ MQTT 上行（IoT 平台）                        │
└────────────────────────────────────────┬───────────────────────────────────────────┘
                                         ▼
┌──────────────────────── 云端：IoT 平台 + 业务后端 ─────────────────────────────────┐
│  IoT 平台：设备接入网关 / 设备影子 / 规则引擎 / 时序存储 / OTA 管理                   │
│  业务后端：账号权限(多租户) / 告警中心 / 通知服务(订阅消息·短信) / 聚合报表 / 开放API  │
└────────────────────────────────────────┬───────────────────────────────────────────┘
                                         ▼
┌──────────────────────── 应用端 ───────────────────────────────────────────────────┐
│  微信小程序·家属端   微信小程序·物业端(值班)   项目后台 Web   物业值班看板   大屏    │
└───────────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 关键选型说明

| 项 | 选型 | 说明 |
|---|---|---|
| **云平台** | **IoT 平台**（阿里云 IoT / 腾讯云 IoT / 华为云 IoT 等） | 负责设备接入、设备影子、规则引擎、OTA、时序存储；业务逻辑放业务后端或云函数 |
| 前端 | **微信小程序 + Web 后台** | 小程序通过 **HTTPS API** 调用业务后端，**不直连设备** |
| 设备上行 | **MQTT over TLS** | 一机一密或一机一证书；物联网平台标准接入 |
| 事件判定 | 设备端 + 云端双层 | 设备即时兜底，云端规则复核 |
| 配网 | 小程序 BLE 优先 / SoftAP 兜底 | 固件外包按附录 A 实现 |

## 3. 功能需求清单

> 优先级：**P0 = MVP 必须** ｜ **P1 = 首个商业化** ｜ **P2 = 商业化迭代** ｜ **P3 = 远期**
> 每条含 **验收标准（AC）**。

### A. 设备端（床垫 + 采集板 + WiFi）· **固件外包**

#### A1 压力采集与预处理 · **P0**
- 32×32 阵列采集，采样 ≥ 15Hz。
- 预处理：滤噪、基线漂移校正、坏点/断线补偿。
- 生成特征：总压力、重心坐标、峰值、`edgePct`、8×8 缩略图、在床判定。
- **AC**：静态基准下漂移 ≤ 5%/8h；特征计算 ≤ 20ms/帧。

#### A2 边缘事件判定 · **P0**
- 设备本地判定：`离床`、`回床`、`坠床风险`、`久卧`、`翻身`。
- 与云端**双保险**（设备即时 + 云端复核）。
- **AC**：事件发生到发出上行包 ≤ 3s（P95）。

#### A3 WiFi 配网 · **P0**
- 支持 **BLE 配网**（首选）与 **SoftAP 配网**（兜底）；小程序内完成。
- 扫码设备 ID → 输入 WiFi → 下发 → 设备回执成功/失败；失败可重试并给出明确指引。
- 支持**一键重置配网**（长按）。
- **AC**：**单床配网 ≤ 3 分钟**，一次成功率 ≥ 90%。

#### A4 联网通信 · **P0**
- **MQTT over TLS** 接入 IoT 平台；一机一密/证书鉴权。
- 心跳默认 30s；事件 QoS1、状态 QoS0。
- **断网缓存 ≥ 24h** 事件；恢复按 `seq` 补传，云端**幂等去重**。
- **AC**：断网 2h 恢复后事件**零丢失**。

#### A5 设备管理与 OTA · **P0（基础）/ P1（OTA）**
- 上报：设备 ID、固件版本、电量、信号强度、在线状态、自检结果。
- **OTA**：差分/整包、**灰度分批**、断点续传、失败回滚（双分区）。
- 指示灯：配网中 / 已联网 / 断网 / 告警。
- **AC**：OTA 成功率 ≥ 98%；失败可回滚。

#### A6 设备安全 · **P0**
- 一机一密（或一机一证书）；固件签名校验；量产关闭调试口。
- **AC**：伪造设备无法上行；非签名固件拒绝刷入。

#### A7 供电与功耗 · **P1（有线）/ P2（电池版）**
- 有线版：DC/USB 常供电。电池版：降频 + 深休眠，**续航 ≥ 30 天**，低电量上报（L2）。
- **AC**：电池版续航 ≥ 目标 80%。

### B. 云端（IoT 平台 + 业务后端）

#### B1 设备接入与设备管理（IoT 平台）· **P0**
- 设备注册/激活/绑定/解绑/停用；设备影子（在线、在床、电量、固件、信号）。
- 支持**批量导入设备**与**一机一密批量烧录信息**。
- **AC**：单平台 ≥ 5000 设备在线；列表可筛选导出。

#### B2 数据存储 · **P0**
- **三层存储**：状态**覆盖写** + 事件**追加** + 统计**定时聚合**（严禁存原始 15Hz 帧）。
- 表/集合：`devices`、`device_status`、`events`、`alerts`、`beds`、`rooms`、`elders`、`users`、`tenants`、`alert_rules`、`stats_hourly`、`stats_daily`、`audit_logs`。
- **AC**：单床日写入 ≤ 2 万条；查询最新状态 ≤ 300ms。

#### B3 规则引擎与告警 · **P0**
- 规则：离床超时、久卧、翻身、**坠床风险**、设备离线、低电量。
- 阈值与**生效时段**支持 **全局 / 项目 / 床位** 三级配置，床位覆盖上级。
- 告警**去重**、**静默期**、**免打扰时段**。
- **AC**：规则改动 1 分钟内生效；去重有效。

#### B4 通知推送 · **P0（订阅消息）/ P1（短信）**
- 渠道：小程序消息中心（兜底）、微信订阅消息、**短信**、（语音外呼可选）、Webhook。
- **分级与升级**（见场景文档 §6）：L3 → 家属 + 物业值班短信 + 小程序；5min 未接单 → 主管；10min → 项目管理员。
- **响应策略可配**：家属优先 / 双通知 / **物业兜底** / 物业主责。
- **AC**：L3 告警产生到手机收到 ≤ 10s（P95）；短信到达率 ≥ 99%。

#### B5 聚合与报表引擎 · **P0（基础）/ P1（导出）**
- 定时任务：小时/日聚合（在床时长、离床次数、翻身次数、告警数与响应时长）。
- 报表：日报/周报/月报；趋势图、事件分布、依从率。导出 Excel/CSV/PDF。
- **AC**：日报自动生成且可与原始事件对账。

#### B6 账号 · 权限 · 多租户 · **P0（权限）/ P1（多租户）**
- RBAC 角色（见场景文档 §4.2）；**租户（物业公司/项目）数据强隔离**。
- 登录：小程序微信授权 / 后台账号密码 + 可选短信验证码。
- **AC**：跨租户越权被拒（含 API 层）。

#### B7 开放 API 与集成 · **P2**
- REST API / Webhook：状态查询、告警推送、档案同步。
- 对接：物业系统/工单系统、社区养老平台、监管平台。
- **AC**：提供 API 文档 + 沙箱；Webhook 支持重试与签名校验。

#### B8 平台运营与运维后台 · **P1**
- 设备监控（在线率、告警数、异常设备）、远程诊断、日志、OTA 发布、租户开通、工单。
- **AC**：可远程定位单设备故障原因。

#### B9 安全与合规 · **P0**
- 传输 TLS1.2+；敏感字段加密存储；最小权限；**审计日志**。
- 个人信息保护：**知情同意**、数据脱敏、留存策略、境内存储。
- 文案合规：对外用"**预警/风险/提醒**"，**禁用**"报警/监护/诊断"。
- **AC**：通过内部安全自查表；隐私政策与同意书齐备。

## 6. 关键数据模型（要点）

| 表/集合 | 键 | 写入方式 | 说明 |
|---|---|---|---|
| `tenants` | tenantId | 少 | 物业公司/项目 |
| `devices` | deviceId | 少 | deviceKeyHash、firmware、bindings、lastTs |
| `device_status` | deviceId | **覆盖写** | inBed/centroid/peak/edgePct/thumb/battery/rssi/online + 状态机时间戳 |
| `events` | eventId | 追加 | leave_bed/return_bed/long_lie/turn/fall_risk/offline |
| `alerts` | alertId | 追加 | type/level/status(待接单/处理中/已处理/已归档)/handler/notes |
| `beds`/`rooms` | bedId/roomId | 少 | 层级与绑定 |
| `elders` | elderId | 少 | 档案 + 同意书状态 |

## 附录 A · 设备接口规格（交付外包固件方）

> 用途：外包固件团队按此实现"设备 ↔ IoT 平台"通信。**改协议 = 改云与小程序，务必一次定对。**

### A.1 设备身份与鉴权
- 一机一密：`productKey` + `deviceName` + `deviceSecret`（或一机一证书）。
- 连接：**MQTT over TLS（8883）**；`clientId` 由三元组派生。

### A.2 上行 Topic 与报文

**① 状态上报**（默认 5s，QoS0）
`topic: /{productKey}/{deviceName}/status`
```json
{
  "deviceId": "BED-0001",
  "seq": 12345,
  "ts": 1757970000000,
  "inBed": true,
  "total": 3421,
  "centroid": [15.2, 18.7],
  "peak": 255,
  "edgePct": 0.12,
  "thumb": [/* 64 个 0-255 */],
  "battery": 87,
  "rssi": -62,
  "fw": "1.0.3"
}
```

**② 事件上报**（即时，QoS1）
`topic: /{productKey}/{deviceName}/event`
```json
{
  "deviceId": "BED-0001",
  "seq": 12346,
  "ts": 1757970012000,
  "event": "leave_bed",
  "payload": {"durationSec": 12}
}
```
- `event` 取值：`leave_bed` / `return_bed` / `long_lie` / `turn` / `fall_risk` / `offline_check`

**③ 心跳/自检**（30s）：`topic: .../heartbeat`，含 `fw`、`battery`、`rssi`、`uptime`

### A.3 下行 Topic 与指令
`topic: /{productKey}/{deviceName}/cmd`
| 指令 | 说明 |
|---|---|
| `set_rules` | 下发阈值（在床阈值、边沿带、久卧时长、生效时段） |
| `ota` | 升级包 URL + 版本 + 校验 |
| `reboot` / `selftest` | 重启 / 自检 |
| `net_config_ack` | 配网结果确认 |

### A.4 断网续传
- 本地队列（Flash）保存未确认的**事件**（≥ 24h），按 `seq` 顺序补传。
- 云端以 `deviceId + seq` **幂等去重**。

### A.5 交付物清单（外包方需给）
1. 固件源码/二进制 + 版本说明
2. 串口/引脚接线图、供电规格
3. 配网实现说明（BLE/SoftAP 服务与特征值定义）
4. 一机一密烧录方案与批量工具
5. OTA 打包与灰度说明

## 附录 B · 帧格式与标定流程

### B.1 什么是"帧格式"
采集板往外吐数据时，那一串字节的**约定格式**。外包固件必须先知道这个约定，才能正确解析出 32×32 的压力值。

**建议帧结构（示例，待真机确认后定稿）**：
```
┌────────┬────────┬────────┬──────────┬───────────────┬────────┐
│ 帧头    │ 长度    │ 序号    │ 时间戳    │ 数据区          │ 校验    │
│ 0xAA55 │ 2 B    │ 2 B    │ 4 B      │ 1024 B(32×32) │ 1 B    │
└────────┴────────┴────────┴──────────┴───────────────┴────────┘
  行优先 uint8，每点 0–255（12-bit ADC → 8-bit），15Hz，波特率 1,000,000
```
- **帧头**：`0xAA55` —— 用于对齐，读串口时先找帧头。
- **长度**：数据区字节数，用于校验完整性。
- **序号**：递增，丢帧可查。
- **校验**：累加/异或/CRC8，校验不过则丢帧重同步。

> 若采集板与 WiFi 模组是**同一主控**（无独立串口），则"帧格式"退化为**内存中的结构体/数组格式**，仍需明确**字段顺序、字节序、缩放系数**。

### B.2 什么是"标定流程"
每张床垫铺好后做的**一次现场校准**。因为床垫软硬、老人体重、是否铺凉席差异极大，不校准就会误报。

**标定步骤（每床必做，引导式）**：
1. **空载基线**：无人上床，连续采集 30s，记录"零值/本底噪声"。
2. **负载标定**：老人（或等重砝码）正常躺卧，采集 1–2 min，记录"总压力区间"。
3. **阈值生成**：
   - 在床阈值 `in_bed` = 基线 + 负载区间的一个比例（如 15–20%）。
   - 床沿带宽度 `edge_band`：距边缘 X 个传感点（按床尺寸）。
   - 坠床风险阈值 `edgePct` 上限。
4. **写入设备**：通过 `set_rules` 下发到设备（设备端兜底判定用），同时存云端（云端复核用）。
5. **验证**：模拟离床/贴边，确认告警触发正确。

**输出物**：每床一条"标定记录"（日期、标定值、标定人），存后台可查。

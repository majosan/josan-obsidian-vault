# 智能床垫压力监测垫系统 · 功能需求（V1.1）

> **系统定义**：面向**物业 / 小区**的柔性压力监测床垫系统。自动识别**坠床风险、离床、久卧不动**等异常，推送告警给**家属亲友与物业值班人员**，并提供数据报表辅助照护决策。
>
> **架构口径**：**去掉 PC 网关**，采集板加装 **WiFi 模组**（**固件外包**），实现 **手机端 → 云端（IoT 平台）→ 设备端** 直连。
>
> **目标**：MVP = **单床位 + 多床位真实演示**（市场推广获单）；商业化 = **多小区/多机构 SaaS 化，百床位规模**。
> **试点**：**老板自有小区物业**；**务必跑出可复制范式**，后续复制到其他小区 / 机构。

## 1. 范围与目标

### 1.1 目标
| 阶段 | 目标 | 成功判据 |
|---|---|---|
| **MVP** | 单床位真实演示 + 多床位真实演示，用于市场推广获取订单 | 现场演示"上床→离床→告警→处理"全链路一次成功 |
| **商业化** | 多小区/多机构 SaaS 化部署，百床位规模 | 单项目 ≥ 200 床稳定运行；新项目开通 ≤ 1 天 |
| **可复制性** | 试点跑通后能低成本复制到其他小区/机构 | 新小区部署 ≤ 1 天，无需定制开发 |

### 1.2 本轮做
- 设备端：WiFi 直连、配网、边缘判定、断网缓存、OTA（**固件外包**）
- 云端：**IoT 平台设备接入**、数据存储、规则告警、多租户、通知推送（**含短信**）、聚合报表、计费订阅、开放 API
- 应用端：**物业端小程序（值班）**、家属端小程序、项目后台 Web、物业看板、（大屏）
- 数据与算法：热力图、姿态、离床/坠床风险/久卧、睡眠/体动、体重估算（迭代）

### 1.3 本轮不做（明确边界）
- 医疗诊断类功能（心率/血氧/呼吸暂停诊断等）
- 视频监控（隐私红线，仅压力感知）
- 同床多人识别
- 独立 App（走微信小程序；商业化再评估）
- 呼叫中心/坐席话务系统（可对接第三方）
- 养老机构专用功能（护理排班、医嘱联动等）——机构场景另开分支

## 2. 系统架构（V1.1）

### 2.1 三层架构

```
┌──────────────────── 设备端（床垫 + 采集板 + WiFi 模组，固件外包）────────────────────┐
│  32×32 柔性压力阵列 → 扫描采集 → MCU 预处理 → 边缘事件判定                          │
│        ├─ 本地指示灯 / 蜂鸣（可选）                                                 │
│        ├─ 本地缓存（断网 ≥ 24h）→ 恢复续传                                          │
│        └─ WiFi 模组（2.4GHz）── TLS ──▶ MQTT 上行（IoT 平台）                        │
└────────────────────────────────────────┬───────────────────────────────────────────┘
                                         ▼
┌──────────────────────── 云端：IoT 平台 + 业务后端 ─────────────────────────────────┐
│  IoT 平台：设备接入网关 / 设备影子 / 规则引擎 / 时序存储 / OTA 管理                   │
│  业务后端：账号权限(多租户) / 告警中心 / 通知服务(订阅消息·短信) / 聚合报表 /          │
│            计费与订阅 / 开放 API                                                     │
└────────────────────────────────────────┬───────────────────────────────────────────┘
                                         ▼
┌──────────────────────── 应用端 ───────────────────────────────────────────────────┐
│  微信小程序·家属端   微信小程序·物业端(值班)   项目后台 Web   物业值班看板   大屏    │
└───────────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 关键选型说明

| 项 | 选型 | 说明 |
|---|---|---|
| **云平台** | **IoT 平台**（阿里云 IoT / 腾讯云 IoT / 华为云 IoT 等） | 设备接入、设备影子、规则引擎、OTA、时序存储；业务逻辑放业务后端 |
| 前端 | **微信小程序 + Web 后台** | 小程序通过 **HTTPS API** 调用业务后端，**不直连设备** |
| 设备上行 | **MQTT over TLS** | 一机一密或一机一证书（详见《设备通信协议与数据规范 v1.0》） |
| 事件判定 | 设备端 + 云端双层 | 设备即时兜底，云端规则复核 |
| 配网 | 小程序 BLE 优先 / SoftAP 兜底 | 固件外包按协议文档实现 |

## 3. 功能需求清单

> 优先级：**P0 = MVP 必须** ｜ **P1 = 首个商业化** ｜ **P2 = 商业化迭代** ｜ **P3 = 远期**；每条含 **验收标准（AC）**。

### A. 设备端（床垫 + 采集板 + WiFi）· **固件外包**

#### A1 压力采集与预处理 · **P0**
- 32×32 阵列采集，采样 ≥ 15Hz；滤噪、基线漂移校正、坏点/断线补偿。
- 生成特征：总压力、重心坐标、峰值、`edgePct`、8×8 缩略图、在床判定。
- **AC**：静态漂移 ≤ 5%/8h；特征计算 ≤ 20ms/帧。

#### A2 边缘事件判定 · **P0**
- 本地判定：`离床`、`回床`、`坠床风险`、`久卧`、`翻身`；与云端**双保险**。
- **AC**：事件发生到发出上行包 ≤ 3s（P95）。

#### A3 WiFi 配网 · **P0**
- **BLE 配网**（首选）/ **SoftAP 配网**（兜底）；小程序内完成；失败可重试并给指引；支持一键重置。
- **AC**：**单床配网 ≤ 3 分钟**，一次成功率 ≥ 90%。

#### A4 联网通信 · **P0**
- MQTT over TLS 接入 IoT 平台；一机一密/证书；心跳 30s；事件 QoS1、状态 QoS0。
- **断网缓存 ≥ 24h**；恢复按 `seq` 补传，云端幂等去重。
- **AC**：断网 2h 恢复后事件**零丢失**。

#### A5 设备管理与 OTA · **P0（基础）/ P1（OTA）**
- 上报：设备 ID、固件版本、电量、信号、在线状态、自检结果。
- OTA：差分/整包、灰度分批、断点续传、失败回滚。
- **AC**：OTA 成功率 ≥ 98%；失败可回滚。

#### A6 设备安全 · **P0**
- 一机一密（或一机一证书）；固件签名校验；量产关闭调试口。
- **AC**：伪造设备无法上行；非签名固件拒绝刷入。

#### A7 供电与功耗 · **P1（有线）/ P2（电池版）**
- 有线常供；电池版降频+深休眠，**续航 ≥ 30 天**，低电量上报（L2）。
- **AC**：电池版续航 ≥ 目标 80%。

### B. 云端（IoT 平台 + 业务后端）

#### B1 设备接入与设备管理 · **P0**
- 设备注册/激活/绑定/解绑/停用；设备影子；批量导入与一机一密批量烧录信息。
- **AC**：单平台 ≥ 5000 设备在线；列表可筛选导出。

#### B2 数据存储 · **P0**
- **三层存储**：状态**覆盖写** + 事件**追加** + 统计**定时聚合**（严禁存原始 15Hz 帧）。
- 表/集合：`devices`、`device_status`、`events`、`alerts`、`beds`、`rooms`、`elders`、`users`、`tenants`、`alert_rules`、`stats_hourly`、`stats_daily`、`billing`、`audit_logs`。
- **AC**：单床日写入 ≤ 2 万条；查询最新状态 ≤ 300ms。

#### B3 规则引擎与告警 · **P0**
- 规则：离床超时、久卧、翻身、**坠床风险**、设备离线、低电量。
- 阈值与生效时段：**全局 / 项目 / 床位** 三级配置；告警去重、静默期、免打扰时段。
- **AC**：规则改动 1 分钟内生效。

#### B4 通知推送 · **P0（订阅消息）/ P1（短信）**
- 渠道：小程序消息中心（兜底）、微信订阅消息、**短信**、（语音外呼可选）、Webhook。
- **分级与升级**：L3 → 家属 + 物业值班（小程序 + 短信）；5min 未接单 → 主管；10min → 项目管理员。
- **响应策略可配**（**默认物业兜底**）：家属优先 / 双通知 / 物业兜底 / 物业主责。
- **AC**：L3 告警到手机 ≤ 10s（P95）；短信到达率 ≥ 99%。

#### B5 聚合与报表引擎 · **P0（基础）/ P1（导出）**
- 小时/日聚合（在床时长、离床次数、翻身次数、告警数与响应时长）；日报/周报/月报；导出 Excel/CSV/PDF。
- **AC**：日报自动生成且可与原始事件对账。

#### B6 账号 · 权限 · 多租户 · **P0（权限）/ P1（多租户）**
- RBAC（见场景文档 §4.2）；租户（物业公司/项目）**数据强隔离**；登录：微信授权 / 账号密码 + 可选短信验证码。
- **AC**：跨租户越权被拒（含 API 层）。

#### B7 开放 API 与集成 · **P2**
- REST API / Webhook：状态查询、告警推送、档案同步；对接物业/工单/社区养老平台。
- **AC**：提供 API 文档 + 沙箱；Webhook 支持重试与签名校验。

#### B8 平台运营与运维后台 · **P1**
- 设备监控（在线率、异常设备）、远程诊断、日志、OTA 发布、租户开通、工单。
- **AC**：可远程定位单设备故障原因。

#### B9 安全与合规 · **P0**
- TLS1.2+、字段加密、最小权限、**审计日志**；知情同意、脱敏、境内存储。
- 文案合规：用"**预警/风险/提醒**"，**禁用**"报警/监护/诊断"。
- **AC**：通过内部安全自查表；隐私政策与同意书齐备。

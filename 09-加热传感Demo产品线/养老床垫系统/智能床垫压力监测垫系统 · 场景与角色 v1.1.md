# 智能床垫压力监测垫系统 · 场景与角色（V1.1）

> **一句话**：一套**面向物业/小区**的柔性压力监测床垫系统 —— 自动识别**坠床风险、离床、久卧不动**等异常，**实时推送告警给家属亲友与物业值班人员**，并以数据报表辅助照护决策。
>
> **架构口径**：**不用 PC 做网关**。采集板加装 **WiFi 模组**，实现 **手机端 → 云端（IoT 平台）→ 设备端** 直连。
> **场景口径**：**面向物业、以小区/居家为主**，**没有护理员**。默认响应人 = **家属/亲友**，物业值班人员为**兜底响应**。

## 1. 产品定位与价值主张

### 1.1 一句话定位
**装在床垫下的一张"压力感知层"**：不说话、不拍视频、不接触皮肤，就能知道老人**在不在床、动不动、有没有往床边滑**，把风险提前几分钟告诉**家属**和**物业值班的人**。

### 1.2 对四方价值

| 对象 | 痛点 | 本系统价值 |
|---|---|---|
| **老人** | 夜起摔倒、久卧压疮、无人知晓 | 无感监测，无需佩戴，隐私友好（**无摄像头、无穿戴**） |
| **家属 / 亲友** | 不在身边、心里没底、怕出事担责 | 手机随时看状态、收告警（含**短信**）、看周报 |
| **物业 / 小区管理员** | 独居老人多、出事要担责、服务缺抓手 | 值班室一屏看风险老人，**上报有据、服务有说法** |
| **物业公司（付费方）** | 需要增值服务卖点、提升续费率与口碑 | 差异化"**安心养老服务**"，可量化、可对外宣传、降低事故赔付风险 |

### 1.3 差异化卖点（对客户讲）
1. **无感无侵入**：不佩戴、不拍摄、不接触皮肤 —— 老人与家属接受度高。
2. **柔性织物传感**：可裁剪/可折叠、贴身合体，不是硬质床垫条。
3. **风险前置**：不是"事后知道掉下床了"，而是**坠床风险预警**（重心持续贴边即报）。
4. **物业可落地**：一张床一套价、按床订阅，**物业是付费方与运营方**，家属是直接受益方。

## 2. 业务模式与客户结构

### 2.1 谁付费 / 谁使用（务必分清）

| 角色 | 是否为付费方 | 是否为日常使用者 |
|---|---|---|
| **物业公司 / 小区物业项目** | ✅ **付费方（B 端）** | ✅ 部署、值班、管理 |
| 家属 / 亲友 | 可自费加购（C 端） | ✅ **默认第一响应人** |
| 老人 | ❌ | ✅ 被监测（**无操作**） |
| 物业 / 小区管理员（管家、值班员、保安、网格员） | ❌ | ✅ 值班响应、上门查看 |

> ⚠️ **本场景无护理员**。养老机构类的"护理员/护士长"角色**不适用于物业/居家场景**，本版已移除。

### 2.2 目标客户分层（GTM）

| 层级 | 画像 | 切入方式 |
|---|---|---|
| **T1 试点（已定）** | **老板自有小区物业**（配合度高） | **自建样板间 + 真实住户试点**；**务求跑出可复制范式**，产出真实案例与数据 |
| **T2 小区/物业项目** | 单个小区物业项目部（几十~几百户） | 物业按床采购/租赁 + 安心养老服务包 |
| **T3 物业集团** | 多小区/多城市的物业集团 | **SaaS 多项目租户** + 年度续费 |
| T4 居家零售 | 独居/空巢老人家庭（子女买单） | 电商/社区渠道/物业代销 |

### 2.3 组织形式（系统要支持的层级）
```
平台（我方）
 └─ 物业公司 / 集团（租户 Tenant）
     └─ 小区 / 项目
         └─ 楼栋 / 单元 / 楼层
             └─ 房间（住户 / 床位）
                 └─ 设备（床垫）
```

### 2.4 商业模式与计费模式（两种并列规划）

> 试点为**老板自有物业**，沟通配合成本低；**但必须按"可复制"标准设计**，以便跑通后复制到**其他小区 / 养老机构**。

| 模式 | 说明 | 收入形态 | 适用 |
|---|---|---|---|
| **A. 按床采购（一次性）** | 物业/机构一次性购买设备（床垫+模组），云服务可含首年 | 硬件 + 首年服务费 | 预算充足、要资产归属的客户 |
| **B. 按年租赁服务（订阅）** | 设备产权归我方，客户按床/年付费，含硬件、云、维护、换新 | **持续性 SaaS 收入** | **推荐主推**：决策门槛低、续费稳定 |

**系统需支持（并列）**：
- 每床/每项目的**计费模式标记**（采购 / 租赁）、**合同起止**、**费用**、**续费提醒**。
- 租赁模式下设备**产权与绑定关系**独立管理（客户到期可回收/换绑）。
- 到期/欠费策略：提醒 → 限制告警推送 → 停服（可配，**不做突然断服**）。

> 商业模式最终口径待与物业沟通后定；**系统两种都支持**，避免后续改架构。

## 3. 场景地图

### 3.1 场景分类维度

| 维度 | 取值 |
|---|---|
| 场所 | **小区居家（主）**、物业值班/日间照料点、独居老人住宅 |
| 居住形态 | 独居、空巢、与子女同住、白天独处 |
| 自理能力 | 自理、半失能、失能、**认知症（阿尔茨海默）** |
| 时段 | 夜间（高风险）、午休、白天独处 |

### 3.2 核心场景清单

> 格式：**场景 → 痛点 → 系统行为 → 成功判据**；**响应人**标明谁去处理。

#### SC-01 夜间离床未归（最高频风险）· 响应人：家属 / 物业值班
- **痛点**：老人夜里起身如厕，长时间未回床；家里没人或子女不在身边。
- **系统行为**：`离床` 事件 → 生效时段（默认 21:00–06:00）内计时 → 超时（可配 5/10/15/30 min）→ **L2 告警**推送家属与物业值班 → 按响应策略升级。
- **成功判据**：超时告警 ≤ 阈值 + 10s 送达；响应人收到。

#### SC-02 坠床风险（贴边/滑落）· 响应人：家属 / 物业值班（上门）
- **痛点**：老人翻身习惯性往床边靠，真正掉下去才发现。
- **系统行为**：在床时检测**压力重心持续贴近/越出床沿带**（`edgePct` 超阈值并持续 T）→ 发 **`坠床风险`（L3 紧急，短信 + 小程序）**；若"贴边后 3s 内离床"也判为高风险。
- **成功判据**：贴边持续 ≥ 设定 T 秒即报；**L3 响应率 100%**（必须有处理记录）。
- **合规口径**：对外称"**坠床风险预警**"，**不称"坠床报警/跌倒报警"**。

#### SC-03 久卧不动 · 防褥疮 · 响应人：家属 / 上门照护
- **痛点**：长期卧床需每 2h 翻身，家里人手不够、容易忘。
- **系统行为**：`久卧不动`（重心变化低于阈值持续 > 2h）与`翻身提醒` → 生成**照护提醒**，写入家属端与物业端待办。
- **成功判据**：提醒生成到处理有记录；周报可统计**翻身依从率**。

#### SC-04 独居老人远程看护 · 响应人：家属（子女）
- **痛点**：子女在外地，父母独居；打电话怕打扰，装摄像头老人抵触。
- **系统行为**：家属端小程序看实时在床/离床、收告警（含短信）、看周报。
- **成功判据**：家属可在 3 次点击内看到"现在在不在床"。

#### SC-05 小区物业集中看护 · 响应人：物业值班
- **痛点**：物业值班室想"一屏看到本小区重点老人"，但缺设备与手段。
- **系统行为**：小区值班看板（在线/在床/告警一屏），L3 告警在值班室声光提示（可选）。
- **成功判据**：一屏覆盖全部试点床位，告警刷新 ≤ 5s。

#### SC-06 认知症老人 · 离床游走/走失 · 响应人：家属 + 物业门岗
- **痛点**：认知症老人无目的起身走动，易走失或摔倒。
- **系统行为**：离床事件**高频聚合并统计趋势**，异常频繁（如夜间多次离床）时推送"行为异常提示"；可配合门岗提醒（后续）。
- **成功判据**：可查看单人离床次数/时段分布图。

#### SC-07 术后/康复短期卧床 · 响应人：家属 / 上门照护
- **痛点**：医嘱要求卧床/限动，患者不自觉下床。
- **系统行为**：按床位配置"限制离床"规则，离床即提醒。
- **成功判据**：离床记录可追溯。

#### SC-08 告警响应闭环（贯穿所有场景）
- **痛点**：告警发了没人看、看了没处理、处理了没记录 —— 出了事无法举证，家属与物业互相推责。
- **系统行为**：告警 → 通知（小程序 + 短信）→ **响应人接单** → **处理 + 备注** → **归档**；全程留痕、可导出。
- **成功判据**：每条告警都有状态流转与处理人；可统计响应时长（**这是物业对家属/监管的核心举证材料**）。

#### SC-09 值班交接 / 上门巡访 · 响应人：物业值班
- **痛点**：物业值班换班靠嘴说，风险老人信息传递失真。
- **系统行为**：交接班视图（当前告警、待办、重点关注老人）；上门巡访打卡（可选）。
- **成功判据**：交接与巡访记录可追溯。

#### SC-10 家属随时安心 · 响应人：家属
- **系统行为**：家属授权看实时状态与周报；可设置只看汇总、不看明细。

#### SC-11 物业运营数据（管理视角）
- **需求**：试点床位数/在线率、告警总数与类型分布、响应时长、异常高发时段；形成**对外服务能力证明**。
- **用途**：物业增值服务宣传、续费谈判、事故举证、集团汇报。

#### SC-12 多小区 / 集团 SaaS 管控（商业化）
- **需求**：租户隔离、跨小区汇总看板、统一规则模板下发、账号与权限集中管理、按床计费。

### 3.3 场景优先级

| 优先级 | 场景 |
|---|---|
| **MVP 必须** | SC-01、SC-02、SC-03、SC-04、SC-05、SC-08 |
| 商业化迭代 | SC-06、SC-07、SC-09、SC-10、SC-11、SC-12 |

## 4. 角色定义

### 4.1 角色卡

#### 【R1】老人（被照护者）
- **目标**：不被折腾、被尊重、有安全感
- **痛点**：抵触穿戴/摄像头；夜里起夜最危险
- **关键任务**：正常睡觉、起夜、翻身（**无操作**）
- **系统触点**：床垫（被动）

#### 【R2】家属 / 亲友（**默认第一响应人**）
- **目标**：随时知道老人状态，出事第一时间知道
- **痛点**：不在身边、信息不对称、怕担责
- **关键任务**：看实时状态、**接收并响应告警（含短信）**、看周报、设定通知人、处理留痕
- **关心**：及时性、准确性、别误报骚扰
- **系统触点**：微信小程序·家属端、**短信**、订阅消息

#### 【R3】物业 / 小区管理员（管家 · 值班员 · 保安 · 网格员）
- **目标**：值班时心里有数，出事能第一时间上门
- **痛点**：独居老人多、责任重、缺手段
- **关键任务**：看小区值班看板、**接单 / 上门查看**、处理留痕、交接班
- **关心**：告警准确（别老误报）、操作快、不额外增加负担
- **系统触点**：小程序·物业端（值班）、值班看板、短信

#### 【R4】物业 / 社区运营主管
- **目标**：服务质量可控、事故可预、能对外讲价值
- **关键任务**：查看告警与响应统计、分配值班、复核高风险住户、导出报表
- **系统触点**：项目后台 Web

#### 【R5】物业公司 / 项目管理员（购买方执行人）
- **目标**：部署简单、成本可控、能对外讲价值
- **关键任务**：建项目/楼栋/房间/床位、绑定设备与老人、开通账号、配置规则模板
- **关心**：**部署是否省事**、售后是否靠谱
- **系统触点**：项目后台 Web

#### 【R6】集团 / 多项目管理员（SaaS 租户管理员）
- **关键任务**：多小区切换、统一规则模板、账号权限、用量与账单

#### 【R7】平台运营 / 我方（客服、实施、运维）
- **关键任务**：设备生命周期管理、远程诊断、OTA 发布、租户开通、告警监控、数据支持

#### 【R8】系统角色 · 床垫设备（WiFi 直连）
- **关键任务**：采集压力 → 边缘判定 → 经 WiFi 上行云端 → 断网缓存续传 → OTA

#### 【R9】第三方系统（可选）
- 物业系统/工单系统、社区养老平台、呼叫中心、监管平台 —— 通过**开放 API / Webhook** 对接

| SC-12 SaaS | 集团 / 平台 | 租户隔离、模板下发、计费 |

## 5. 关键用户旅程

### 5.1 夜间告警闭环（最核心旅程）
```
凌晨 02:14  独居老人起身离床
   │ 设备 3s 内判定「离床」→ WiFi 上行云端
   ▼
02:14:03   云端规则：生效时段内 + 计时开始
   ▼
02:24:03   超时 10 分钟未回床 → 生成 L2「离床超时」告警
   ▼
02:24:05   ① 家属端小程序订阅消息 → 子女手机
           ② 物业值班端看板该床变红（按策略）
   ▼
02:25:10   家属「接单」→ 电话/上门确认 → 「已处理」+ 备注
           （若家属设了"物业兜底"，物业值班同时收到并可上门）
   ▼
02:31:00   老人回床 → 自动生成「回床」事件，告警自动归档
   ▼
次日       运营主管在后台看到：响应时长 1 分 07 秒、处理人、备注
```
- **关键指标**：告警送达 ≤ 10s（P95）；响应率 100%；响应时长可统计。

### 5.2 响应策略（可配置，物业场景关键）
| 策略 | 说明 | 适用 |
|---|---|---|
| **家属优先** | 只通知家属，物业不介入 | 家属同住/就近 |
| **双通知** | 家属 + 物业值班同时收到 | 独居、家属较远 |
| **物业兜底** | 先通知家属，N 分钟未响应自动转物业值班 | **独居老人推荐** |
| **物业主责** | 物业值班为主，家属仅可见 | 物业集中照护点 |

### 5.3 家属开通旅程（物业代开）
```
物业管理员后台录入老人档案 → 扫码绑定设备/床位 → 微信分享邀请家属
        ▼
家属点开小程序 → 授权（知情同意）→ 看到实时状态 → 开启订阅消息 + 填手机号（短信）
        ▼
收告警 / 每周一自动收到周报
```

### 5.4 物业批量部署旅程（决定成单效率）
```
到货 → 管理员后台批量导入楼栋/房间/床位（Excel）→ 逐个扫码绑定设备
     → 小程序扫码配网（WiFi）→ 设备上线自检 → 试铺一张床做阈值校准
     → 批量复制规则模板 → 全小区铺开
```
- **要求**：**单床配网 ≤ 3 分钟**，支持批量模板，配网失败有明确指引（能否规模化落地的关键）。

## 6. 告警闭环与升级机制

### 6.1 告警分级

| 级别 | 类型 | 通知渠道 | 要求 |
|---|---|---|---|
| **L1 提示** | 翻身提醒、久卧提醒 | 小程序消息中心 + 看板黄色 | 可批量处理，不强制留痕 |
| **L2 重要** | 离床超时、回床异常、设备电量低 | 微信订阅消息 + 看板橙色 | 需接单处理 |
| **L3 紧急** | **坠床风险**、设备离线、SOS（可选硬件） | 订阅消息 + **短信** + 看板声光 | **必须处理+留痕**，支持升级 |

### 6.2 升级规则（Escalation）
```
L3 告警发出 → 短信 + 小程序通知「家属 + 物业值班」
            → 5 min 未接单 → 通知物业运营主管
            → 10 min 未处理 → 通知项目管理员（并再次提醒家属）
L2 告警发出 → 30 min 未接单 → 通知物业运营主管
```

### 6.3 告警去重与静默
- 同一床位 + 同一类型，在**事件窗口**内只报一次（避免刷屏）。
- 支持"**静默期**"（如已知老人下床如厕，可临时静音 N 分钟）。
- 支持**免打扰时段**（默认 22:00–06:00 仅 L2/L3 推送）。

### 6.4 通知渠道矩阵

| 渠道 | L1 | L2 | L3 | 备注 |
|---|---|---|---|---|
| 小程序消息中心 | ✅ | ✅ | ✅ | 兜底，必到 |
| 微信订阅消息 | — | ✅ | ✅ | 需用户订阅 |
| **短信** | — | — | ✅ | **已确认要做**；发家属 + 物业值班 |
| 语音外呼 | — | — | 可选 | 商业化评估 |
| 看板声光提示 | — | — | ✅ | 物业值班室 |

## 7. 业务规则与假设

| # | 规则 | 默认值 | 可配置层级 |
|---|---|---|---|
| 1 | 离床判定 | 无压力持续 **3s** | 全局/项目 |
| 2 | 离床超时告警 | **30 min** | 床位级 |
| 3 | 久卧不动 | 重心变化 < 阈值，持续 **2h** | 床位级 |
| 4 | 翻身提醒间隔 | **2h** | 床位级 |
| 5 | 坠床风险边沿阈值 | `edgePct` > 阈值持续 **2s** | 床位级（需标定） |
| 6 | 生效时段 | **21:00–06:00** | 项目/床位 |
| 7 | 设备离线判定 | 无上行 > **2 min** | 全局 |
| 8 | 状态上行间隔 | **5s**（可 10/30s） | 项目 |
| 9 | 响应策略 | **物业兜底**（家属未响应 N 分钟自动转物业值班）· **默认** | 床位级 |
| 10 | 阈值逐床校准 | 首次铺床校准流程 | 床位级 |

**关键假设**：
- 一张床垫 = 一位老人（不处理同床两人场景）。
- 设备需 2.4GHz WiFi 覆盖（住户家中 WiFi 或物业统一部署热点）。
- 老人/家属**知情同意**后方可开通。
- **本版不涉及"护理员"**；如需机构场景，另开需求分支。

## 8. 术语表

| 术语 | 含义 |
|---|---|
| 在床 / 离床 | `inBed` 状态，由总压力阈值判定 |
| 压力重心 | 全床压力的加权质心坐标（越靠边越危险） |
| `edgePct` | 边沿带压力占全床压力比例，坠床风险核心指标 |
| 坠床风险预警 | 重心持续贴边/快速离床的高风险事件（**非医疗报警**） |
| 久卧不动 | 长时间无明显体动，压疮风险 |
| 事件 vs 告警 | 事件 = 客观发生（离床）；告警 = 需人响应的通知（离床超时） |
| **响应人** | 收到告警后负责处理的人（家属 / 物业值班） |
| 响应策略 | 家属优先 / 双通知 / 物业兜底 / 物业主责 |
| 租户 | 一个物业公司/项目的隔离单元 |
| 配网 | 将设备连入 WiFi 并绑定云端账号的过程（BLE/SoftAP） |

# 设备通信协议与数据规范（V1.0）

> **用途**：定义**智能床垫设备端 ↔ 云端** 的全部通信约定。既是**固件外包方的实现依据**，也是**云端与小程序开发的对接基准**。
> **原则**：协议一次定对，**改协议 = 云与端全改**。本文档为**唯一权威口径**，功能需求文档不再重复。
> **状态**：草案（默认值已给出，真机联调后定稿为 V1.0 Final）。

---

## 0. 术语与约定

| 术语 | 含义 |
|---|---|
| 设备（Device） | 床垫 + 采集板 + WiFi 模组 的整机 |
| 主控（MCU） | 采集板上的处理器 |
| 模组（Module） | WiFi 通信模组（可为主控一体） |
| 上行（Up） | 设备 → 云端 |
| 下行（Down） | 云端 → 设备 |
| 事件（Event） | 需即时上报的状态变化（离床/坠床风险等） |
| 状态（Status） | 周期性上报的最新快照 |
| 字节序 | **大端（Big-Endian）**，除非特别说明 |
| 时间 | Unix 毫秒时间戳（int64，UTC） |

**协议版本**：本文档定义 `protoVer = 1`，所有报文携带 `protoVer` 字段，用于向后兼容。

## 1. 通信架构

```
┌─────────────────── 设备端 ───────────────────┐
│ 32×32 压力阵列 → 采集 → MCU 预处理/边缘判定    │
│                        │                      │
│                  帧格式(§10)                   │
│                        ▼                      │
│  [可选] 采集板 ⇄ 主控/模组（若为分离方案）      │
│                        │                      │
│                   WiFi 模组                    │
└────────────────────────┬──────────────────────┘
                         │  MQTT over TLS(8883)
                         ▼
┌─────────────── IoT 平台（设备接入层）───────────┐
│  鉴权 / 设备影子 / 规则引擎 / 时序存储 / OTA     │
└────────────────────────┬──────────────────────┘
                         │  规则转发 / API
                         ▼
┌─────────────────── 业务后端 ───────────────────┐
│  告警中心 / 通知(小程序·短信) / 聚合报表 / 计费   │
└────────────────────────┬──────────────────────┘
                         ▼
                    小程序 / Web 后台
```

**核心原则**：
1. 设备**只与 IoT 平台通信**，不直连业务后端。
2. 手机端**只与业务后端通信**，不直连设备（除 BLE 配网）。
3. 设备端做**即时兜底判定**，云端做**权威复核**。

## 2. 设备身份与鉴权

### 2.1 身份三元组（一机一密）
| 字段 | 说明 | 示例 |
|---|---|---|
| `productKey` | 产品标识（同型号共用） | `pk_bedmatt_01` |
| `deviceName` | 设备唯一名（即 `deviceId`） | `BED-0001` |
| `deviceSecret` | 设备密钥（**每台唯一**） | `b7f3…`（32+ 字符） |

- 支持升级为**一机一证书（X.509）**方案，量产前定稿。
- `deviceId` 命名规则：`BED-` + 4 位序号（如 `BED-0001`），与床位一对一绑定。

### 2.2 连接参数
| 项 | 值 |
|---|---|
| `clientId` | `{productKey}&{deviceName}`（按平台规则，可含 `|securemode=2,signmethod=hmacsha256|`） |
| `username` | `{deviceName}&{productKey}` |
| `password` | HMAC-SHA256(`clientId`,`deviceSecret`) 或平台指定签名 |
| 端口 | **8883（TLS）** |

### 2.3 密钥烧录
- 由我方生成密钥表（Excel/CSV），外包方按**批量烧录工具**写入，**不可读出**。
- 烧录后**关闭调试口**，量产固件**禁止打印密钥**。

## 3. 网络与连接管理

| 项 | 约定 |
|---|---|
| WiFi | **2.4GHz**（不支持 5GHz）；802.11 b/g/n |
| 协议 | **MQTT 3.1.1**（或 5.0），**TLS 1.2+** |
| KeepAlive | **30s** |
| Clean Session | **false**（保留订阅与离线消息） |
| 重连 | 指数退避：1s→2s→4s→…→最长 60s；重连成功上报一次状态 |
| 断网判定 | 连续 3 次心跳无响应 → 进入缓存模式（§8） |
| 心跳/自检 | 每 **30s** 上报一次（§5.3） |
| NTP | 联网后立即对时，之后每 6h 一次；对时失败用本地时钟，`timeSynced=false` |

## 4. Topic 规范

| 方向 | Topic | QoS | Retain | 说明 |
|---|---|---|---|---|
| 上行 | `/{pk}/{dn}/up/status` | 0 | 否 | 周期状态 |
| 上行 | `/{pk}/{dn}/up/event` | **1** | 否 | 即时事件 |
| 上行 | `/{pk}/{dn}/up/heartbeat` | 0 | 否 | 心跳/自检 |
| 上行 | `/{pk}/{dn}/up/ack` | 1 | 否 | 指令响应 |
| 下行 | `/{pk}/{dn}/down/cmd` | 1 | 否 | 云端指令 |
| 下行 | `/{pk}/{dn}/down/ota` | 1 | 否 | OTA 通知 |
| 下行 | `/{pk}/{dn}/down/netcfg` | 1 | 否 | 配网结果回执（经模组/小程序链路） |

> `{pk}` = productKey，`{dn}` = deviceName。

## 6. 事件定义与判定口径（**设备端与云端必须一致**）

| 事件 | 触发条件（默认） | `level` | payload 示例 |
|---|---|---|---|
| `leave_bed` | `inBed` 由 true→false，且离床持续 ≥ **3s**（去抖） | info | `{"durationSec":0}` |
| `return_bed` | `inBed` 由 false→true 持续 ≥ **3s** | info | `{"outDurationSec":3720}` |
| `fall_risk` | ① `edgePct` > `edgeThreshold` 持续 ≥ **2s**；**或** ② 离床前 3s 内 `edgePct` > 阈值（快速滑落） | **alert** | `{"edgePct":0.42,"trigger":"edge_hold"}` |
| `long_lie` | 重心位移 < `motionThreshold` 持续 ≥ **2h** | warn | `{"durationMin":120}` |
| `turn` | 距上次显著体动（重心位移 > 阈值）≥ `turnIntervalMin`（默认 120min） | info | `{"sinceLastTurnMin":121}` |
| `offline_check` | 设备本地自检异常 / 主动上报健康问题 | warn | `{"reason":"sensor_noise"}` |
| `selftest_fail` | 自检不通过 | warn | `{"item":"adc"}` |

**统一约定**：
- **去抖**：所有状态翻转需**持续时间门槛**（默认 3s），避免抖动误报。
- **阈值来源**：优先用**下发的 `set_rules` 值**，缺省用**出厂默认**（见 §15）。
- **事件与状态并存**：事件包=即时（低延迟）；状态包=周期快照（对账）。
- **去重键**：`deviceId + seq`（云端幂等）。

```json
{
  "protoVer": 1,
  "cmdId": "c-88213",
  "cmd": "set_rules",
  "params": {
    "inBedThreshold": 520,
    "edgeBandCells": 3,
    "edgeThreshold": 0.30,
    "leaveHoldSec": 3,
    "longLieMin": 120,
    "turnIntervalMin": 120,
    "activeWindows": [["21:00","06:00"]],

  }

```

| cmd | params | 说明 |
|---|---|---|
| `set_rules` | 见上 | 下发阈值与规则（**标定后下发**） |
| `set_report_interval` | `{"reportIntervalSec":10}` | 调整状态上报间隔 |
| `selftest` | `{}` | 触发自检 |
| `reboot` | `{}` | 重启 |

## 8. 断网缓存与续传

| 项 | 约定 |
|---|---|
| 缓存内容 | **事件包**（必留）+ 最近状态（可只留最新） |
| 容量 | ≥ **24h**事件（按日均 ≤ 200 条/床估算，建议 ≥ 4096 条，Flash 循环队列） |
| 序号 | `seq` **全局单调递增**，跨断网不重置（回绕按 uint32） |
| 补传 | 恢复连接后**按 seq 升序**补传；QoS1 未确认则重发 |
| 幂等 | 云端以 `deviceId+seq` 去重；重复上报**不重复计告警** |
| 溢出策略 | 队列满则**丢最旧**（绝不停采、绝不阻塞采集线程） |
| 补传限速 | ≤ 10 条/s，避免打爆网络 |

## 9. 时钟与时间处理

- 设备联网后 **NTP 对时**（`ntp.aliyun.com` 等，可配）。
- 报文携带 `ts`（设备时间）；IoT 平台/云端另记 `cloudTs`（接收时间）。
- 云端以 **设备 `ts` 为准**做事件排序与窗口判定；若 `|ts - cloudTs| > 5min` 标记 `timeAnomaly` 并告警（设备时钟异常）。
- 断网期间 `ts` 用本地时钟，`timeSynced=false`；续传时保留原 `ts`。

## 10. 采集板 ↔ 主控/模组 帧格式（若为分离方案）

> 若采集板与 WiFi 模组为**同一主控**，本节退化为"内存结构体约定"，仍需固定**字段顺序、字节序、缩放系数**。

### 10.1 帧结构

| 偏移 | 字段 | 长度 | 说明 |
|---|---|---|---|
| 0 | 帧头 | 2 B | **`0xAA 0x55`** |
| 2 | 版本 | 1 B | 帧协议版本，=1 |
| 3 | 长度 | 2 B | 数据区字节数（大端） |
| 5 | 序号 | 2 B | 0–65535 循环 |
| 7 | 时间戳 | 4 B | 相对开机毫秒（大端） |
| 11 | 数据区 | 1024 B | **32×32 行优先 uint8**，每点 0–255 |
| 1035 | 校验 | 2 B | **CRC16-CCITT（多项式 0x1021，初值 0xFFFF）**，覆盖版本~数据区 |

> 总长 = 1037 B/帧；15Hz → 约 15.6 KB/s；串口波特率 **1,000,000**（可降为 921600/460800）。

### 10.2 解析规则
1. 逐字节搜索帧头 `AA 55`（失步后重新同步）。
2. 校验 `长度` 与 `CRC16`，不过则**丢帧并继续找帧头**。
3. `seq` 不连续 → 记丢帧数（诊断上报）。
4. 数据点：`value` 为 8-bit 归一值；原始 12-bit ADC → `value = round(adc * 255 / 4095)`。
5. **坏点补偿**：与相邻 4 点差值超阈的孤立点，用邻域中值替换（可选，设备端或云端均可）。

## 11. 配网规范（BLE 优先 / SoftAP 兜底）

### 11.1 BLE 配网（首选）
| 项 | 约定 |
|---|---|
| 广播名 | `BEDCFG-{deviceId 后4位}` |
| 服务 UUID | `0xFFE0`（自定义，待定稿统一注册） |
| 写特征 | `0xFFE1`：手机 → 设备，写入配网指令（JSON，分片 ≤ 200B，含 `chunkIdx/total`） |
| 通知特征 | `0xFFE2`：设备 → 手机，回执进度/结果 |
| 配网载荷 | `{"ssid":"…","password":"…","token":"…","region":"…"}` |
| 超时 | 广播 **3 min** 无连接自动关闭；连接后 **60s** 内未完成则失败 |

### 11.2 SoftAP 兜底
- 设备起 AP：SSID `BED-{deviceId后4位}`，无密码或固定密码（标签印刷）。
- 手机连 AP → 小程序 HTTP 提交 SSID/密码 → 设备切换 STA → 回执。

### 11.3 配网流程与结果码
```
扫码获取 deviceId → 手机 BLE 连接设备 → 下发 WiFi + token
   → 设备连 WiFi → 连 IoT 平台成功 → 回执手机（成功）
   → 若失败：回执错误码，手机提示重试
```
| code | 含义 | 用户提示 |
|---|---|---|
| 0 | 成功 | 配网成功 |
| 1 | WiFi 密码错 | 请检查密码 |
| 2 | 未找到 SSID | 请确认是 2.4G 网络 |
| 3 | 信号过弱 | 请靠近路由器重试 |
| 4 | 云端连接失败 | 请稍后重试 |
| 5 | token 无效/绑定冲突 | 请联系管理员解绑 |

**AC**：单床配网 ≤ 3 分钟，一次成功率 ≥ 90%。

## 12. OTA 规范

```json
{
  "protoVer": 1,
  "cmdId": "c-90001",
  "cmd": "ota",
  "params": {
    "version": "1.0.4",
    "url": "https://…/fw_1.0.4_diff.bin",
    "size": 262144,
    "sha256": "…",
    "mode": "diff",
    "force": false
  }
}
```
| 项 | 约定 |
|---|---|
| 分区 | **双分区（A/B）**，升级失败自动回滚 |
| 校验 | 下载后校验 `sha256` + **固件签名** |
| 断点续传 | 支持 Range 请求 |
| 灰度 | 按**批次/百分比**下发；先试点床 |
| 上报 | 升级过程上报进度与结果（`up/ack` + `up/event`） |
| 兼容 | 升级**不改变** `protoVer` 语义；如需变更协议须升 protoVer 并向后兼容 |

**AC**：OTA 成功率 ≥ 98%；失败可回滚到可用版本。

## 13. 安全要求

1. 传输：**TLS 1.2+**，禁止明文 MQTT。
2. 身份：一机一密 / 一机一证书；密钥**不可读出**（加密存储 + 读保护）。
3. 固件：**签名校验**后才可运行 / 刷入。
4. 调试口：量产关闭（JTAG/UART 调试通道）。
5. 上行鉴权：一律经 IoT 平台，**禁止设备直连业务后端**。
6. 隐私：不上传任何可识别个人的信息（不含姓名/身份证/电话）；仅设备 ID 与传感特征。
7. 防重放：`seq` + `ts` 校验；异常时间戳拒收。
8. 可选防拆：外壳开关触发 `offline_check`。

## 15. 标定流程规范

### 15.1 目标
每张床铺装后做**一次现场校准**，生成该床专属阈值（床垫软硬、体重、凉席差异极大）。

### 15.2 流程（引导式，物业/家属按提示操作）

| 步 | 操作 | 记录 |
|---|---|---|
| 1 | **空载基线**：无人上床，静置采集 **30s** | `baseline`（均值+噪声 σ） |
| 2 | **负载标定**：老人（或等重砝码）正常躺卧 **1–2 min** | `loadedTotal`、`centroidRange` |
| 3 | **自动生成阈值** | `inBedThreshold = baseline + k*(loadedTotal-baseline)`（k 默认 0.15） |
| 4 | **边沿带** | `edgeBandCells` 按床尺寸（默认距边 3 格） |
| 5 | **下发设备** | 通过 `set_rules` 下发（设备兜底用）+ 存云端（复核用） |
| 6 | **验证** | 模拟离床 / 贴边，确认触发正确 |

### 15.3 默认阈值（未标定时）
| 参数 | 默认值 |
|---|---|
| `inBedThreshold` | 按空载基线 + 经验值（待实测标定） |

### 15.4 标定记录
每床一条记录：`bedId / 日期 / 标定值 / 标定人 / 验证结果`，存后台可查、可重做。

## 16. 版本兼容策略

- 报文含 `protoVer`；云端**同时兼容**相邻版本（至少向后 1 个版本）。
- 新增字段**只增不改**；字段废弃先标记 `deprecated`，下个大版本移除。
- 设备固件版本与协议版本解耦：固件升级不必然变更协议。
- 兼容性检查在 **P0 阶段用真实设备验证**。

## 18. 附：完整时序（示例）

```
[设备上电]
   ├─ 读取已存 WiFi → 尝试连接 → 连上 → MQTT 连接 → NTP 对时
   │      └─ 上报 status(timeSynced=true) → 进入正常循环（status/5s + heartbeat/30s）
   └─ 无 WiFi 配置 → 进入配网广播（BLE 3min / SoftAP）

[配网]
   手机小程序 --BLE 写 0xFFE1--> 设备
   设备 --回执 0xFFE2--> 手机（code=0）
   设备 --MQTT connect--> IoT 平台 --影子更新--> 业务后端 → 小程序看板"设备上线"

[事件]
   老人离床 → 设备 3s 去抖判定 → up/event(leave_bed, QoS1)
   → IoT 平台 → 业务后端规则（生效时段计时）
   → 超时 → 生成告警 → 通知服务 → 小程序订阅消息 + 短信（L3）
   → 处理人接单/处理 → 写入 alerts（含处理人、耗时）

[断网]
   心跳失败 3 次 → 缓存模式 → 事件入 Flash 队列
   网络恢复 → 按 seq 补传 → 云端去重入库 → 状态回正常

[OTA]
   云端下发 ota(version/url/sha256) → 设备下载(断点续传) → 校验+签名
   → 写入 B 分区 → 重启切换 → 上报结果 → 失败自动回滚
```

# 织物传感空间化与「场景包」概念（V0.1）

> **一句话**：把同一套柔性织物传感技术，从"一张床垫"扩展到**卫生间、床边、活动区等关键点位**，用**事件与状态**（而非连续轨迹）构建"全屋跌倒/活动风险守护"，形成可分场景售卖、可分阶段落地的**"场景包"**产品线。
>
> **口径前提（已定）**：通信沿用 **2.4 GHz WiFi + MQTT**，不改协议；本文件是**产品概念**，不改变当前"床垫 MVP 先跑通付费闭环"的主线。

---

## 0. 缘起

- 当前主线产品 = **智能床垫压力监测垫**（单床：离床 / 坠床风险 / 久卧）。
- Josan 提出：传感布本质是"一块布"，可否不止床上——**厕所扶手、墙面、地面都布置**，做**全屋老人运动轨迹 + 实时位置/状态**，把故事升级为"场景"。
- 本文件对该想法做**可行性论证 + 落地化重构**，结论是：**方向对，但表述要改（"轨迹"→"关键点位事件"），且分阶段落地，不现在铺开**。

---

## 1. 技术现实：压力织物"能做什么 / 不能做什么"

这是全篇最关键的判断，先说清，避免对客户/投资人过度承诺。

| 能力 | 压力织物（我们） | 说明 |
|---|---|---|
| 感知"有人踩/压在上面"（踩压点、力大小） | ✅ 可以 | 阵列越密越准 |
| 感知"停留时长、受力变化、体动" | ✅ 可以 | 有时间序列即可推事件 |
| 感知"从 A 连续走到 B 的平滑轨迹" | ❌ **做不到** | 只能得到**离散踩压点**，点与点之间是"推断"，不是"测量" |
| 感知"没被覆盖区域之外的人" | ❌ 做不到 | 传感只在其铺设范围内生效 |
| 区分"是谁" | ❌ 基本做不到（压力式） | 除非叠加其他模态 |

> **现实可得的成果**：**"关键点位 + 时间序列"** → 推"**去过哪些点 / 各停留多久 / 步态节奏 / 是否在某个点跌倒**"。
> **不可得的成果**：**"实时画出老人运动轨迹"**（除非整屋铺满高密度阵列，成本/施工/清洁/耐久均为灾难级）。

**能做"全屋实时位置"的正解技术**（作为对照/备选）：
- **电容式地面**（如德国 **SensFloor**：地板下电容层，检测位置/步态/跌倒，已在欧洲护理机构应用）——**最接近本构想的现成对标物，但它是电容不是压力织物**（细节待核实）。
- **UWB / 毫米波雷达**：位置准、隐私好，成本高。
- **摄像头**：最准但隐私最差，养老场景强抵触。

---

## 2. 口径修正：用"事件与状态"，不用"轨迹"

对外/对内统一改口径，既守住可实现性，又保住故事：

| ❌ 不建议的说法 | ✅ 建议的说法 |
|---|---|
| 全屋实时运动轨迹 | 关键点位感知 + 行为事件推断 |
| 实时定位老人在哪 | 识别老人**在哪个区域、停留多久、是否跌倒/久留** |
| 绘制移动路径 | 下床后**路径关键点**（床边→走廊→卫生间）+ 时序 |

> 结论：**故事不用改小（"全屋跌倒与活动风险守护"依然成立），只是把承诺收敛到"测得到的东西"。**

---

## 3. "场景包"产品构想

把空间布点打包成**可独立销售、可组合**的"场景包"，每个包 = 若干点位 + 传感类型 + 可推事件 + 价值主张。同一采集板 / 同一协议 / 同一云。

### 3.1 场景包清单（建议）

| 场景包 | 布点 | 传感类型 | 可推事件 | 价值 / 风险 |
|---|---|---|---|---|
| **床边包**（与床垫配套首发） | 床侧地垫 | 压力阵列 | 下床→落地→离开/返回、床边久站、跌倒 | 夜间坠床/起夜风险闭环 |
| **卫生间包**（价值最高） | 马桶前地垫、淋浴区地垫、**扶手**、门口 | 地垫=压力；扶手=**电容触摸/接近** | 如厕时长异常、久留、淋浴滞留、扶手受力（起身艰难）、卫生间内跌倒 | **卫生间是跌倒最高风险区**，也是"单点位传感"价值最高的地方 |
| **活动包** | 沙发/座椅垫、常走位地垫 | 压力阵列 | 久坐、离座、起坐困难、活动量趋势 | 活动能力/衰弱趋势 |
| **整屋包**（远期） | 地面整片 + 多点 | 压力 + 电容混合 | 区域级位置、步态、跌倒 | 需解决铺装/供电/清洁/耐久 |

### 3.2 为什么"卫生间包"是第一优先
1. **风险密度最高**：跌倒、晕厥、久留（突发疾病）多发于卫生间。
2. **技术最匹配**：空间小、点位少 → **少量点位 + 事件推断**即可显著覆盖风险，不必整屋铺。
3. **对标差异**：Wisbi 只覆盖"床"；我们天然可延伸到"**床边→卫生间**"这条最危险的动线。
4. **成本可控**：2–3 个点位 + 复用现有采集板/协议/云，边际成本低。

---

## 4. 技术选型：不同点位用不同传感（别硬用压力织物）

| 点位 | 推荐传感 | 理由 |
|---|---|---|
| 地垫（压力） | **压阻织物阵列**（现有技术） | 承重、贴身、隐私友好 |
| **扶手 / 墙面** | **电容式触摸/接近传感** | 扶手测的是"手扶/抓握/依靠"，**电容比压力更合适**（人手靠近即感知），且不受坐压影响 |
| 整屋位置 | 电容地面 / UWB（远期备选） | 压力织物做不出连续轨迹 |

> **务必区分**：扶手/墙面**不是压力传感器的用武之地**，属另一条技术栈（电容）。选型阶段就要分开，避免"拿压力布贴扶手"这种错配。

---

## 5. 落地路径（分阶段，不偏离主线）

| 阶段 | 内容 | 依赖 | 时机 |
|---|---|---|---|
| **阶段1（现在）** | 床垫 MVP：把付费闭环 + 可复制范式跑出来 | 固件外包、IoT 平台、小程序 | 当前主线 |
| **阶段2（下一步）** | **床边地垫 + 卫生间地垫**（2–3 点位），复用同一采集板/协议/云，识别"下床路径 + 如厕滞留 + 跌倒高风险" | 需先做**概念验证 demo**：能证明"用离散点推行为事件" | MVP 稳定后 |
| **阶段3（远期）** | 扶手/墙面（**电容式**）+ 地面整片（或雷达），做区域级位置/步态 | 需新传感技术栈 + 施工/供电方案 | 商业化规模化后 |

**建议的第一件事（低成本验证）**：做一个 **"床边地垫 + 马桶前地垫"概念验证**——用现有压力阵列 + 现有采集板，验证事件识别准确率。成了再谈"场景包"产品化。

---

## 6. 与现有系统的复用（不改协议）

- **传感 / 采集板 / 边缘判定**：可复用（同 32×32 稀疏阵列思路，按场景改尺寸/密度）。
- **通信**：**沿用 2.4 GHz WiFi + MQTT over TLS**（已定，不改），新增点位即新增设备/子设备。
- **云端 / 告警 / 小程序**：复用现有告警中心、响应策略、报表。
- **数据模型**：需新增"**点位/区域（zone）**"层（如 `zones` / `zone_events`），在现有 项目→楼栋→房间→床位 之下扩展"**区域→点位**"。

> 结论：**场景包 = 现有系统的"空间维度扩展"，不是重做。** 架构与协议基本不变，主要在数据模型加"区域/点位"层。

---

## 7. 风险与边界（必须写进对外口径）

1. **不做"轨迹"承诺**（技术不可达）——统一说"关键点位 + 行为事件"。
2. **地面/卫生间耐久是最大风险**：踩踏、拖洗、高湿——**我们连床上耐久都还没测**（规格书"疲劳 ≥5 万次"仍为待验证）。地面产品必须先解决耐久与清洁。
3. **供电/走线**：多点位全屋布点需解决"每点怎么供电/通信"，否则满屋电线；可参考电池 + 低功耗上报思路（**但协议已定 WiFi，电池版续航受限，需专门评估**）。
4. **隐私与合规**：沿用"无摄像头、无穿戴"卖点；但**扩展到家更多区域**后，知情同意与数据边界要重新明确。
5. **不要现在铺开**：全屋是**第二产品线/远期**，当前资源应集中"床垫 MVP 跑通付费闭环"，避免回到"目标不唯一"的老问题。

---

## 8. 结论

- **方向成立、故事更好**：从"床垫单品"→"**空间化养老守护平台**"，且隐私友好，是对 Wisbi 等床垫竞品的天然升级（**床 → 床边 → 卫生间**这条动线）。
- **但要改口径**：**"关键点位 + 行为事件"**，不承诺"实时轨迹"。
- **要分场景、分阶段**：**卫生间包优先**；先做床边+卫生间概念验证，再谈产品化；**扶手/墙面走电容传感**。
- **复用为主**：协议/采集板/云不动，数据模型加"区域/点位"层。

> 一句话给 Josan：**这个想法很好，是"从产品到平台"的升级；但请用"关键点位感知 + 行为事件推断"来定义它，并把它放在床垫 MVP 跑通之后。**

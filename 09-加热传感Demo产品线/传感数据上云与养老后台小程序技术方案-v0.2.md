# 传感布数据上云 + 养老后台/小程序 技术方案（V0.2）

> **用途**：32×32 传感布 → PC 网关（Python）→ 微信云开发 → 后台管理系统 + 小程序，全链路技术方案。
> **场景**：第一锚点 = 养老（压力传感床垫 / 轮椅垫），后台看板 + 家属端/护工端小程序。

### 2.2 多设备（真实，非模拟）

- 每台设备 = 一块采集板 + 一条串口。**一台 PC 网关可对接多个串口**，`deviceId ↔ 串口` 由 `config.yaml` 映射。
- 每个串口起**独立读线程**，共用同一个环形缓冲池与上云转发线程（按 `deviceId` 分桶）。
- `deviceId` 格式建议 `BED-0001`，与床位绑定。

### 2.3 设备接入层抽象（**V0.2 关键**）

> **PC 网关 = 将来的 WiFi 模组**。现在把"设备该怎么跟云说话"一次设计对，将来只换实现、不换协议。

| 现在 | 将来（加 WiFi 模块后） |
|---|---|
| PC（Python）读串口 → 提特征 → POST | 带 WiFi 的小 MCU 模块（如 ESP32）读串口 → 同逻辑固件 → POST |
| 采集板不变，照旧吐原生帧 | 采集板**基本不变**；后面串一个模组 |
| BLE/WiFi 配网：无 | 蓝牙做首次配网，WiFi 做上传 |
| **云端 + 小程序** | **零改动** |

→ 网关里 `FrameSource` 做成接口，`SerialSource` / `MockSource` / `ReplaySource` 可替换；将来固件按同一 `ingest` 协议实现即可。

## 3. PC 端网关改造（Python）

### 3.1 线程/进程结构（互不阻塞）

| 线程 | 职责 | 原则 |
|---|---|---|
| **① 读串口（每串口一个）** | 收帧 → 丢进环形缓冲 | **只读不处理，绝不阻塞** |
| **② 本地可视化** | 从缓冲取最新帧画图 | 保留现有代码 |
| **③ 上云转发** | 取最新帧 → 特征提取 → 降频 → POST | 失败静默重试，不拖累 ①② |

> **铁律**：网络发送**不能**在串口读取线程里做。网络一卡，整个采集就死。

### 3.2 环形缓冲（防卡死核心）

```python
from collections import deque
frame_q = deque(maxlen=200)   # 满则自动丢最老帧
```
- 读线程 `append`；可视化线程读 `[-1]`；转发线程也取 `[-1]`；多设备用 `dict[deviceId] -> deque`。
- **满了丢老的，绝不反压** —— 采集永远"真"，只有展示/上云可能丢帧。

### 3.3 降频策略（直接决定云端成本）

| 数据 | 频率 | 说明 |
|---|---|---|
| 本地可视化 | **15 Hz** | 给人看，不能降 |
| 上云·状态 | **默认 0.2 Hz（每 5s）** | 家属端看"在床/离床"足够，可配 5/10/30s |
| 上云·事件 | **事件触发立刻发** | 离床、久卧、翻身、**坠床风险**、设备离线 |
| 上云·聚合 | 云函数定时（每小时/每天） | 生成报表数据 |

### 3.4 特征提取（关键！别传原始 1024 点）

**传原始数据上云 = 烧钱**。32×32 原始点 → 精简成"特征包"：

| 特征 | 计算 | 字节 |
|---|---|---|
| 压力分布缩略图 | 32×32 下采样到 **8×8**（4×4 块均值） | 64 B |
| 总压力 | 所有点求和 | 4 B |
| 压力重心 (x,y) | 加权质心 | 8 B |
| 峰值压力 | max | 2 B |
| **边沿占比 `edgePct`** | **边沿带压力 / 总压力（坠床风险用，V0.2 新增）** | 4 B |
| 在床判定 | 总压力 > 阈值 | 1 B |
| 时间戳 / 设备ID / seq | | 12 B |
| **合计** | | **≈90 B**（vs 原来 1024 B，省 11×） |

> 原始 1024 点数据：**只留在 PC 本地**（local sqlite/文件供回溯），**不上云**。云端只存特征与事件。

### 3.5 断线容错

- POST 失败 → **静默跳过**（本地可视化不受影响）
- 事件类数据（告警）→ 本地落盘 **sqlite 队列**，恢复后**按 seq 补传**，云端按 `deviceId+seq` **幂等去重**
- 超时设 3s，重试退避，避免堆积线程

### 3.6 Python 代码骨架（可直接改造）

```python
import time, threading, requests, yaml
from collections import deque
from sources import make_sources      # SerialSource / MockSource / ReplaySource

CFG = yaml.safe_load(open("config.yaml"))
frame_q: dict[str, deque] = {s["device_id"]: deque(maxlen=200) for s in CFG["serial"]}
stop = threading.Event()

# ---------- ① 读串口（每设备一个线程）----------
def reader(src):
    for frame in src.frames():        # 真串口 / 模拟器 / 回放，接口统一
        frame_q[src.device_id].append(frame)

# ---------- ③ 上云转发（单线程轮询各设备）----------
def extract(frame):
    thumb  = downsample_8x8(frame)                 # 4x4 块均值
    total  = sum(frame)
    cx, cy = centroid(frame)
    edge   = edge_ratio(frame, band=CFG["thresholds"]["edge_band"])
    return {"deviceId": DEVICE_ID, "ts": int(time.time()*1000),
            "inBed": total > CFG["thresholds"]["in_bed"], "total": total,
            "centroid": [round(cx,2), round(cy,2)], "peak": max(frame),
            "edgePct": round(edge,3), "thumb": thumb, "event": None}

def cloud_pusher():
    last = {}
    while not stop.is_set():
        for did, q in frame_q.items():
            if q and time.time() - last.get(did, 0) >= CFG["cloud"]["up_interval_sec"]:
                try:
                    requests.post(CFG["cloud"]["ingest_url"], json=extract(q[-1]),
                                  headers={"X-Device-Key": CFG["cloud"]["device_key"]}, timeout=3)
                    last[did] = time.time()
                except Exception:
                    pass                   # 断网：跳过，不影响本地

# 启动：为每个串口起 reader(src)，再起 cloud_pusher()，主线程跑本地可视化
```

> 改动量：现有可视化代码只需把"读串口"换成"读环形缓冲"，其余逻辑不动。

- 波特率 1,000,000

### 4.2 上云数据包（精简特征包，JSON）

```json
{
  "deviceId": "BED-0001",
  "ts": 1757970000000,
  "seq": 12345,
  "inBed": true,
  "total": 3421,
  "centroid": [15.2, 18.7],
  "peak": 255,
  "edgePct": 0.12,
  "thumb": [ /* 64 个 0-255 */ ],

```
- Header：`X-Device-Key`


## 5. 微信云开发侧

### 5.1 用到的云开发能力

| 能力 | 用途 |
|---|---|
| **云函数** | `ingest`、`query`、`alert-handle`、`bind`、`report`、`cron-stat` |
| **云数据库** | 设备状态、事件、告警、用户、统计 |
| **HTTP 访问服务 / HTTP API** | 让 PC 网关把数据 POST 进来 |
| **订阅消息** | 告警推送到微信 |
| 静态网站托管 | 后台管理系统 |

> PC 怎么接云开发：① 云函数配置 **HTTP 访问服务** → PC 直接 POST（推荐）；② **HTTP API**（AppID+AppSecret 换 token）。**必须加自定义密钥 header 鉴权**。

### 5.2 数据模型（集合设计）—— 成本敏感

> ⚠️ **绝对不要**把 15Hz 原始帧写进云数据库。按"**状态覆盖 + 事件追加 + 定时聚合**"三层存：

| 集合 | 写入方式 | 内容 | 量级 |
|---|---|---|---|
| `devices` | 少量 | `deviceId`、`bedId`、`deviceKeyHash`、`lastTs`、`online` | 静态/少量 |
| `device_status` | **覆盖写同一条** | 最新 `inBed/centroid/peak/edgePct/thumb/lastTs/online` + 状态机 `inBedSince/outBedSince/edgeSince/lastTurnTs` | 每设备 1 条 |
| `events` | 事件触发追加 | 离床、回床、久卧、翻身、坠床风险、设备离线 | 每天几十条 |
| `alerts` | 告警触发追加 | 类型/级别/床位/状态(待处理/已处理) | 每天几条~几十条 |
| `beds` | 少量 | 床位、房间、机构、绑定设备、老人 | 静态 |
| `elders` | 少量 | 老人档案（姓名/性别/年龄/地址/电话/紧急联系人/人群标签/知情同意） | 静态 |
| `users` | 少量 | openid、角色（家属/护工/管理员）、关联床位 | 静态 |
| `alert_rules` | 少量（可覆盖全局默认） | 生效时段、离床超时、坠床阈值、久卧/翻身时长 | 少量 |
| `stats_hourly` / `stats_daily` | **定时云函数**聚合 | 在床时长、离床次数、翻身次数、告警数 | 每床每小时/天 1 条 |

**写入量对比**（单床）：原始帧 15Hz 直存 1,296,000/天 ❌；状态 5s 覆盖写 ≈17,280/天 ⚠️；状态 10s 覆盖写 ≈8,640/天 ✅。
> 建议：状态上行间隔做成**配置项**（默认 5s，可调 10/30s）；多床（≥5 张）直接上付费套餐。

### 5.3 云函数清单

| 云函数 | 触发 | 职责 |
|---|---|---|
| `ingest` | HTTP（PC POST） | 鉴权 → 校验 → 幂等去重 → 覆盖写 `device_status` → 规则判断 → 写 `events`/`alerts` → 发订阅消息 |
| `query` | 小程序/后台调用 | 返回某床最新状态 / 事件列表 / 告警列表 / 报表（按角色过滤） |
| `alert-handle` | 小程序/后台调用 | 护工处理告警（改状态、写处理人/备注） |
| `bind` | 小程序/后台调用 | 绑定/解绑 `设备↔床位↔用户`、建老人档案（**配网降级版**） |
| `report` | 后台调用 | 生成/导出报表（xlsx/csv） |
| `cron-stat` | 定时触发器（每小时/每天） | 聚合写 `stats_*`；判设备离线 |

### 5.4 告警规则（`ingest` + `cron-stat`）

| 规则 | 判定 | 级别 |
|---|---|---|
| 离床 `leave_bed` | `inBed` 由 true→false，在**生效时段**内持续 > 15/30/60min（可配） | 中/高 |
| 久卧不动 `long_lie` | 重心变化 < 阈值 且持续 > 2h | 高（压疮风险） |
| 翻身提醒 `turn` | 距上次翻身 > 设定时长 | 中 |
| **坠床风险 `fall_risk`** | 在床时 `edgePct` > 阈值持续 > 2s；**或** 贴边后 3s 内离床 | **高** |
| 设备离线 `offline` | `lastTs` 超时（> 2min 无上报） | 高 |

> 阈值与**生效时段**全部**可配置**（`alert_rules`，默认 21:00–06:00）；告警**按事件窗口去重**，避免刷屏。

### 5.5 订阅消息（告警推送）

- 用小程序**订阅消息**推送告警到家属/护工微信（需申请模板 ID，用户需主动订阅）
- 兜底：小程序内"消息中心"列表 + 后台看板轮询

## 8. 关键工程注意点（踩坑清单）

1. **降频 + 聚合是一切的底线** —— 原始帧别上云
2. **多设备 ID 现在就留字段** —— 后台多床位前提（本轮**真实多设备**）
3. **网络与采集解耦** —— 环形缓冲 + 独立线程
4. **时钟同步** —— PC 用 NTP 对时，否则事件时间戳错乱
5. **在床/边沿阈值需标定** —— 逐床校准，阈值可配
6. **云端鉴权** —— PC 上行加密钥 header，防伪造
7. **离线兜底** —— 事件本地落盘补传；云端 `lastTs` 超时判离线
8. **缩略图 vs 原始数据** —— 云端存 8×8，原始留本地
9. **告警去重** —— 同一事件窗口只报一次
10. **文案合规** —— 用"预警/风险"，不用"报警/医疗监护"

# 传感床垫软件 · 需求与范围（V0.1）

> **一句话**：本轮把「压力传感床垫 → 云端 → 小程序（家属端/护工端）+ 后台管理」这条链路做成**可演示、可交付机构的完整闭环**，硬件**不加 WiFi/蓝牙**，先由 PC 当「设备接入网关」。

---

## 1. 背景与目标

- 传感床垫 Demo 线的软件侧要从"本地热力图"升级为"**养老场景可演示的完整闭环**"。
- 本轮目标：**家属端 + 护工端 + 后台管理** 三端打通，能演示「床垫 → 后端 → 小程序/后台」的端到端链路。
- 硬件现状：**无 WiFi、无蓝牙模块** → 由 PC 走串口读数据，充当**设备接入网关**上云。将来再加 WiFi/蓝牙模块时，**PC 网关逻辑整体移植为固件**，云端/小程序**零改动**。

### ✅ 今天（2026-09-20）已定决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | 端形态 | **微信小程序**（不做独立 App） |
| 2 | 后端技术栈 | **微信云开发**（免备案、免服务器） |
| 3 | 本轮 PC 网关 | **按"未来可被 WiFi 模组替代"的协议设计**（协议一次做对，将来不返工） |
| 4 | 本轮范围 | **P0 闭环 + P1 一起做** |
| 5 | 硬件改动 | **本轮零改动**（不加 WiFi/蓝牙） |
| 6 | 配网 | **降级为"后台绑定/建档"**（无 BLE/WiFi 硬件，真配网待模块到位） |
| 7 | 多床看板 | **按真实设备做**（每台设备一条串口，PC 网关多串口对接，非模拟） |
| 8 | 坠床风险 | **纳入**（口径为"坠床**风险**预警"，非"坠床报警"） |
| 9 | 心率 | **不做**（压力/体动传感测不到心率，且涉及医疗宣称） |

---

## 2. 本轮范围（做什么 / 不做什么）

### 2.1 做

- **设备接入层（PC 网关）**：多串口接入、特征提取、降频上云、断网补传、本地可视化保留
- **云端**：数据接收/存储、告警规则判定、订阅消息推送、定时聚合
- **小程序·家属端**：绑定、实时状态、告警列表、周报
- **小程序·护工端**：多床位看板、告警处理
- **后台管理（Web）**：多床看板、告警管理、设备/床位/老人档案、报表导出
- **绑定/建档流程**（配网降级版）
- **多床**：真实多设备（多串口）

### 2.2 不做（本轮）

- 真蓝牙/WiFi 配网（硬件没有）
- 心率 / 生命体征（传感器能力外）
- 呼叫中心（坐席、来电弹屏、话务报表、投诉）
- 预警运营中心（人工坐席判断、110/120 联动、话务回访）
- 多级地图（全国/省/市/区/镇/村/社区）
- 办公/资讯/通用系统管理类模块（将来用低代码顶）
- 医疗宣称类功能（"监护""报警"等措辞不对外用）

---

## 3. 场景与角色

- **场景**：养老（机构 + 居家两条），本轮演示以**居家/机构床垫**为主。
- **角色**：
  - **家属**：看老人的在床/离床状态、收告警、看周报
  - **护理员/护工**：看多床状态、处理告警
  - **管理员/机构**：床位与设备管理、报表
  - **设备**：传感床垫（经 PC 网关上云）

---

## 4. 功能需求

### 4.1 设备接入层（PC 网关）

| 功能 | 要求 |
|---|---|
| 多设备接入 | 一个 PC 网关支持**多串口、多设备**（`deviceId ↔ 串口` 由配置映射） |
| 采集解耦 | 读串口 / 本地可视化 / 上云转发 **三线程互不阻塞**；环形缓冲，满则丢老帧 |
| 特征提取 | 32×32 原始点 → **8×8 缩略图 + 总压力 + 重心 + 峰值 + 边沿占比 + 在床判定**（≈90B，不上传原始 1024 点） |
| 降频 | 状态默认 **5s 一次**（可配）；**事件即时上报** |
| 事件判定 | 本地判定：离床/回床/久卧/翻身/坠床风险（也可放云端，二者取一，建议**云端统一判定**、本地只做"兜底/即时"） |
| 断网补传 | 事件本地落盘（sqlite），恢复后**按 seq 补传**，去重 |
| 鉴权 | 上行带 `X-Device-Key` |
| 本地可视化 | 保留现有热力图；只把"读串口"改成"读缓冲" |
| 时钟 | PC 侧 NTP 对时，保证事件时间戳可信 |

### 4.2 云端

| 功能 | 要求 |
|---|---|
| 接收 | `ingest`：鉴权 → 校验 → 覆盖写设备状态 → 规则判定 → 写事件/告警 → 推订阅消息 |
| 存储 | 三层：**状态覆盖写 + 事件追加 + 定时聚合**（详见技术方案 V0.2） |
| 告警规则 | 离床 / 久卧 / 翻身 / **坠床风险** / 设备离线，阈值与生效时段**全部可配** |
| 推送 | 小程序**订阅消息**；兜底：消息中心列表 + 看板轮询 |
| 聚合 | 定时云函数生成小时/日报表数据 |

### 4.3 小程序

**家属端（P0）**
- 绑定床位 / 设备
- 首页 · 实时状态（在床/离床、大图标、最近告警）
- 告警列表 + 详情
- 周报（在床时长、离床次数、翻身次数、告警统计）
- 我的（绑定管理、订阅设置）

**护工端（P1）**
- 多床位看板（在线/在床/告警一屏总览）
- 告警处理（接单、处理、备注）
- 任务（翻身提醒）

### 4.4 后台管理（Web）

- 多床位实时看板
- 告警列表 + 处理流转
- 历史数据查询（按床 / 时间）
- **报表导出**（Excel/PDF：在床时长、离床次数、告警统计）
- 设备管理 / 床位绑定
- 老人档案（含人群标签：留守 / 空巢 / 独居 / 半失能 / 失能 / 普通家庭）

### 4.5 配网 / 绑定（降级口径）

- 无 BLE/WiFi 硬件 → **不做真配网**。
- 本轮流程：**扫码（或手输）设备 ID → 选择/新建床位 → 绑定老人 → 完成**。
- UX 先立起来，将来模块到位只需"接线"（不改前后端交互）。

### 4.6 告警规则

| 类型 | 判定 | 级别 |
|---|---|---|
| 离床 `leave_bed` | `inBed` 由 true→false，且在**生效时段内**持续 > N 分钟（默认 30，可配 15/30/60） | 中/高 |
| 久卧不动 `long_lie` | 重心变化 < 阈值 且持续 > 2h | 高（压疮风险） |
| 翻身提醒 `turn` | 距上次翻身 > 设定时长 | 中 |
| **坠床风险 `fall_risk`** | 在床时**重心持续贴近/越出床沿带**（`edgePct` > 阈值 持续 T）；**或**"在床→离床"过程中离床前重心贴边且离床过程**极短（< 3s）** | 高 |
| 设备离线 `offline` | `lastTs` 超时（> 2min 无上报） | 高 |

- **生效时段**：可配，默认 **21:00–06:00**（起夜未归 / 防摔倒场景）。
- 阈值：**全部可配 + 逐床校准**（床垫软硬、体重、是否铺凉席等差异大）。

## 5. 暂缓项（记录，不做）

- 心率/生命体征（传感器能力外）
- 真 BLE/WiFi 配网（等硬件）
- 4G 模块（协议留接口，硬件后置）
- 呼叫中心 / 运营坐席 / 多级地图 / 通用后台脚手架
- SOS 一键报警（列为"可搭配硬件"，后续接）

# 织物传感空间化与场景包（功能定义 · 卖点话术）V0.1

> **一句话**：在床垫之外，把同一套柔性织物传感铺到**关键点位**，用"**停留时长 + 活动节奏**"识别**久留、跌倒、游走、规律变化**——**既服务老人，也服务宠物**，形成可分场景售卖、可分阶段落地的「**场景包**」。
>
> **口径前提**：通信沿用 **2.4 GHz WiFi + MQTT**（不改协议）；**不做"连续轨迹"，只做"关键点位 + 行为事件"**（技术现实）。
> **适用对象（两条线）**：① **老人/养老**（物业/居家/机构）；② **宠物**（猫狗家庭）。

---

## 1. 定位与基本口径

| 项 | 口径 |
|---|---|
| 产品形态 | 关键点位（地垫 / 扶手 / 墙面板）传感 + 复用现有采集板 / 云 / 小程序 |
| 核心指标 | **区域停留时长、停留次数、时段分布、区域体动/倒伏** |
| 不承诺 | ❌ 连续运动轨迹 ❌ 精确"在哪一格" ❌ 医疗/兽医诊断 |
| 传感选型 | 地垫 = 压力织物阵列；**扶手 / 墙面 = 电容式触摸/接近**（非压力） |
| 通信 | 2.4 GHz WiFi + MQTT（**保持不动**） |
| 数据模型 | 现有 项目→楼栋→房间→床位 之下扩展 **区域(zone)→点位(point)** |
| 目标对象 | **老人**（主）+ **宠物**（次/扩展）|

## 2. 场景包清单（可独立售卖 / 可组合）

### 2.1 养老场景包

| 场景包 | 点位 | 传感 | 主打功能 | 优先级 |
|---|---|---|---|---|
| **卫生间包** ⭐ | 马桶前地垫、淋浴区地垫、扶手、门口 | 地垫=压力；扶手=电容 | 久留预警、跌倒、如厕规律 | **P0（旗舰）** |
| **床边包** | 床侧地垫 | 压力阵列 | 下床→落地→离开/返回、床边久站 | P0（与床垫配套首发） |
| **活动包** | 沙发/座椅垫、常走位地垫 | 压力阵列 | 久坐、起坐困难、活动量趋势 | P1 |
| **整屋包** | 地面整片 + 多点 | 压力 + 电容混合 | 区域级位置、步态、跌倒 | P2（远期） |

> **为什么"卫生间包"是旗舰**：① 跌倒/晕厥/突发疾病**风险密度最高**；② 空间小、点位少 → **少量点位 + 事件推断**就能显著覆盖；③ **摄像头做得到但没人愿意装** → 隐私友好是差异化；④ Wisbi 只覆盖"床"，我们天然延伸到"**床边→卫生间**"最危险动线。

### 2.2 宠物场景包 🆕

| 场景包 | 点位 | 传感 | 主打功能 | 优先级 |
|---|---|---|---|---|
| **猫砂盆包** ⭐ | 猫砂盆前/下方地垫 | 压力阵列 | **如厕次数 + 停留时长**（泌尿健康信号） | **P0（旗舰）** |
| **门口包** | 门内地垫 | 压力阵列 | **分离焦虑**（久留/来回踱步） | P1 |
| **进食包** | 食盆/水盆下地垫 | 压力阵列 | 进食/饮水停留异常（食欲下降早提示） | P1 |
| **睡窝包** | 窝垫 | 压力阵列 | 睡眠时长、活动量趋势 | P1 |
| **全屋宠物包** | 多点点位 | 压力（+ 可选摄像头） | 走到哪、各区停留、异常 | P2 |

> **为什么做宠物**：① **技术完全复用**——"区域占用 + 停留时长 + 节奏"本就是我们的强项；② **宠物独处时间长**（上班族），主人有"看不见的焦虑"；③ **摄像头难覆盖全屋、成本高**，且宠物会躲镜头/被遮挡——**点位传感更现实**；④ 竞品 **威海矩侨已上"宠物监测（带后台软件）"**，**市场已被验证**，我们可切入（差异化见 §5.5）。

## 3. 核心功能定义 —— 养老

> 所有功能输出均为**事件/状态**（非轨迹）；告警分级沿用系统 L1/L2/L3。

### F1 · 久留预警（Dwell Alarm）★旗舰
- **定义**：为每个区域设"正常最长停留时间"，超时即分级告警。
- **数据**：区域占用状态 + 连续停留计时（离开即清零）。
- **触发**：停留 > 阈值（卫生间建议 **15 min**，可配）→ **L2**；再超（如 30 min）或伴随倒伏 → **L3（短信+小程序）**。
- **价值**：覆盖**跌倒/晕厥/突发疾病/被困**——"不用等摔倒，进去太久就有人问一句"。
- **卖点一句话**：**"不是等他摔倒才报警，而是他进去太久没出来就提醒你。"**

### F2 · 区域跌倒 / 异常倒伏
- **定义**：区域内压力面瞬间铺开 + 长时间低体动 → 判"倒伏"；结合"由站到躺/无起身"签名。
- **触发**：区域内检测到倒伏 → **L3**；**定位到区域**（卫生间/走廊）缩短救援。
- **口径**：对外称"**跌倒风险/倒伏提示**"，避用"跌倒报警"。

### F3 · 夜间起夜安全闭环（组合故事）★
- **动线**：床垫（离床）→ 走廊 → 卫生间（滞留/倒伏）→ 返回床。
- **逻辑**：离床后计时，任一环节异常（滞留/未按时返回/倒伏）→ 逐级升级。
- **价值**：一条动线讲完，风险全覆盖；把床垫与场景包**捆绑成一个方案**卖。
- **卖点一句话**：**"从下床到回床，这一整段路，我们都盯着。"**

### F4 · 生活规律画像 / 趋势（健康向）
- **定义**：按区域统计停留时长、次数、时段分布，出行/周/月趋势。
- **触发**：偏离个人基线（夜间起夜↑、如厕时长↑）→ **L1 提示**（非告警）。
- **价值**："作息变化本身就是信号"（泌尿/感染等早期提示——**只做趋势提示，不涉诊断**）。
- **卖点一句话**：**"看不见的时候，也能知道爸妈的作息有没有变。"**

### F5 · 区域久坐 / 久卧 → `>2h` 提醒（**L1**）；F6 · 认知症游走（夜间跨区频次超阈 → **L2**）；F7 · 区域占用/在离（基础状态，所有上层功能的地基）。

## 4. 核心功能定义 —— 宠物 🆕

> 与养老同源：**区域占用 + 停留时长 + 节奏**；差异只在对象与话术。**不涉隐私**（用户对宠物摄像头顾虑小），核心卖点是**"全屋覆盖 + 无感 + 数据化"**。

### P1 · 宠物区域占用（走到哪、在不在某区）
- 实时"哪个点位有人（有宠）、停留多久" —— 所有宠物功能的基础。

### P2 · 猫砂盆使用监测 ★旗舰
- **定义**：猫砂盆点位记录**如厕次数 + 每次停留时长**，出行/周趋势。
- **触发**：次数异常↑/↓、单次停留显著变长、夜间频繁 → **提示（非诊断）**。
- **价值**：**猫的泌尿系统疾病（尿闭、膀胱炎）早期最典型信号就是"频繁跑猫砂盆/蹲很久"**——早发现能救命。
- **卖点一句话**：**"猫的泌尿病，早发现就差这一步——它上了几次猫砂盆、蹲了多久。"**

### P3 · 分离焦虑（门口久留/来回踱步）
- **定义**：门内点位长时间占用 + 反复触发 → 判"分离焦虑/等待主人"。
- **触发**：超阈 → **提示**（可推送"你家猫在门口等了 40 分钟"）。

### P4 · 进食 / 饮水停留异常
- **定义**：食盆/水盆点位停留时长/频次下降 → 食欲/饮水变化提示（生病早筛）。

### P5 · 睡眠 / 活动量趋势
- **定义**：窝垫停留时长（睡眠）、各点位总触发量（活动量）→ 趋势；下降提示"可能不舒服"。

## 5. 卖点话术库

### 5.1 对家属（子女）
- 一句话版：**"父母的卫生间和夜间起夜，我们帮你盯着——不用装摄像头。"**
- 30 秒版：老人最怕两件事——"出事没人知道"和"身体悄悄变差"。摄像头老人抵触、保姆太贵。传感垫铺在卫生间/床边，**无感、不拍人**：进去太久没出来会提醒你；夜间起夜异常也提醒；每周一份作息趋势。
- 异议应对：与摄像头比 → **隐私**；与手环比 → **不用戴、不用充电**。

### 5.2 对物业 / 小区
- **"把风险最高的卫生间和洗浴区守住，出事有据、服务有说法。"** 增值服务卖点 + 事故举证 + 降担责。

### 5.3 对机构（养老院/护理）
- **"护理员不用整晚巡房，系统告诉你去哪一间、哪一刻。"** 减巡房、降褥疮与跌倒后果。

### 5.4 对宠物主人 🆕
- 一句话版：**"上班不在家，也知道猫砂盆上了几次、待了多久——不用满屋装摄像头。"**
- 30 秒版：猫狗独处最容易"生病了你却不知道"。摄像头只能看一个房间、还看不全、宠物会躲；我们把传感垫铺在**猫砂盆、门口、食盆、窝**这些关键位置，**无感记录**它的如厕、等待、进食、睡眠——**泌尿病、食欲下降、分离焦虑，都能早一步发现**。
- 异议应对：
  - "摄像头不就行了？" → 摄像头**难覆盖全屋**、宠物会躲、多房间成本高；**点位传感更现实**。
  - "对宠物有隐私问题吗？" → **基本没有**（用户共识），我们主打**覆盖 + 无感 + 数据**。

### 5.5 差异化（对外口径）
| 对比 | 短板 | 我们的差异 |
|---|---|---|
| 摄像头（养老） | 隐私差、老人抵触 | **无画面、无穿戴** |
| 摄像头（宠物） | 难覆盖全屋、宠物躲镜头、成本高 | **关键点位覆盖 + 无感** |
| 手环/雷达 | 要戴、要充电 / 贵 | **铺好即用、无感** |
| Wisbi 等床垫 | 只覆盖"床"、**二值报警** | **延伸到全屋动线 + 连续压力分布 + 停留时长** |
| 矩侨宠物监测 | 已上市（带后台），**提前布局** | **同一技术栈可同时覆盖"养老 + 宠物"两条线**（一鱼两吃） |

> ⚠️ **竞品提示**：**威海矩侨工业科技**（我方最直接竞品）在展会已展出"**宠物监测 + 后台软件**" → 宠物方向**已有玩家验证**，我们切入没问题，但要**靠"养老+宠物同一技术栈/同一后台"做差异化**，不正面拼单品。

## 6. 产品组合与售卖

- **售卖形态**：床垫（基础）+ **场景包（可选）**；宠物线单独成包。
- **计费**：沿用现有 **按点位/按区域采购 + 按年租赁**；场景包按点位/区域/包计价。
- **推荐组合**：
  - 养老：`床垫 + 卫生间包`（旗舰组合，一晚动线闭环）；机构可加 `活动包`。
  - 宠物：`猫砂盆包`（旗舰）起步，可加 `门口包 / 进食包 / 睡窝包`。
- **共用后台**：养老与宠物**共用同一套云/小程序/告警/报表**（只是对象不同）——**边际成本低、一份研发两条线**。

---

## 7. 技术实现要点（复用为主）

- **传感**：地垫复用现有**压力阵列 + 采集板**（按场景改尺寸/密度）；**扶手/墙面另需电容式传感**（另一条技术栈）。
- **通信 / 云 / 小程序 / 告警 / 报表**：**全部复用**，新增点位即新增设备/子设备。
- **数据模型**：新增 `zones` / `zone_events`（区域→点位层），**人为"老人"或"宠物"仅是一个对象类型（subject_type）**——架构上同一套。
- **算法**：以"**占用状态机 + 停留计时 + 倒伏签名 + 基线偏离**"为主，不依赖高精度定位。

## 8. 落地路径

| 阶段 | 内容 | 时机 |
|---|---|---|
| 阶段1 | 床垫 MVP：付费闭环 + 可复制范式 | **现在（主线）** |
| 阶段2 | **床边 + 卫生间**概念验证（2–3 点位），验证 F1–F4 准确率 | MVP 稳定后 |
| 阶段2b | **宠物线**：`猫砂盆包`概念验证（单点位起步，最轻量、最快出结果） | 可与阶段2 并行/择机 |
| 阶段3 | 扶手/墙面（电容）+ 地面整片 / 雷达（区域位置） | 商业化规模化后 |

> **第一件事**：做"**床边 + 马桶前**"两点的低成本概念验证，验证"停留时长 + 倒伏"识别率。**宠物线可从"猫砂盆单点"切入**（点位最少、价值最集中）。

## 9. 风险与边界（对外红线）

1. **不承诺"轨迹/精确位置"**——统一说"关键点位 + 行为事件"。
2. **不涉医疗/兽医诊断**——趋势只做"提示"。
3. **地面/卫生间耐久是最大风险**：踩踏、拖洗、高湿；床上耐久尚未测（规格书疲劳 ≥5 万次待验证）。宠物线的**踩踏/抓挠/尿**也考验耐久与清洁。
4. **供电/走线**：多点位需解决供电/通信；协议已定 WiFi，**电池版续航受限**（专门评估）。
5. **不要现在铺开**——当前集中"床垫 MVP 跑通付费闭环"；场景包（含宠物）是下一步，别动摇主线。

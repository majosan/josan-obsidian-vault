# 技术架构总览

> **决策时间**：2026-07-24
> **核心变更**：从 LabVLA 端到端 VLA 路线 → **分层架构**
> **关联硬件**：宇树 G1-D 旗舰版C (U8) / 触觉手套 / Intel RealSense D435

---

## 一、为什么放弃端到端 VLA

LabVLA（Qwen3-VL-4B + DiT）是一个"当前可行解"，但不是化学实验室的终局方案：

| 问题 | 说明 |
|------|------|
| **模型架构锁定** | 一个模型包揽"看+理解+动"，两头都顾不好 |
| **动作精度不够** | 末端 delta 输出，~cm 级；化学实验需要 ±0.15mm，差两个数量级 |
| **触觉融合困难** | LabVLA 输入槽写死（state_dim=8），改架构等于重预训练 |
| **长任务不支持** | 5 步以内短 horizon，DRIFTS 需要 24 步流程 |
| **硬件抽象缺乏** | 只跑过 Franka 单臂，没有双臂/轮式底盘/灵巧手支持 |

**趋势判断**：业界共识正向分层架构迁移（DeepMind RT-X、1X NEO、Figure Helix 都走这个方向）。

## 二、推荐架构

### 三层结构

```
┌──────────────────────────────────────────────────────────────┐
│  🧠 L1: 大脑 (Frontier LLM)    ☁️ 云端 API                    │
│  ┌─────────┐ ┌─────────┐ ┌───────────┐ ┌──────────┐         │
│  │ SOP 理解 │ │ 任务规划 │ │ 安全监控   │ │ 科研推理  │         │
│  └─────────┘ └─────────┘ └───────────┘ └──────────┘         │
│  频率: 0.1-1 Hz · 延迟 2-5s · 输出符号指令                   │
├──────────────────────────────────────────────────────────────┤
│  ⚡ L2: 小脑 (Specialist)      🏢 本地服务器 GPU              │
│                                                             │
│  ① 场景感知模型                                             │
│     SAM2 + DINOv2 → 物体检测 + 3D 位姿                       │
│     训练：微调（不是从头训练），500-2000 张实验室照片           │
│     部署：🏢 服务器（需 ~8GB VRAM，Jetson 内存不够）          │
│                                                             │
│  ② 技能策略模型 ← 核心训练对象                                │
│     Diffusion Policy → 条件输入生成关节轨迹                    │
│     训练：BC(500-2000次示教) → RL(仿真10万-100万步) → 真机微调  │
│     部署：🤖 Jetson Orin（~500MB 权重，本地推理 10-30ms）      │
│                                                             │
│  ③ 技能选择器                                                │
│     轻量 MLP + 规则引擎 → 选技能 + 适配参数                    │
│     部署：🤖 Jetson（CPU 即可）                              │
├──────────────────────────────────────────────────────────────┤
│  🦾 L3: 脊髓 (Classical Control)  🤖 机器人本地              │
│                                                             │
│  ① 视觉伺服（AprilTag）→ ±0.05mm 精对准                      │
│     部署：Jetson 本地（OpenCV，不需要 GPU）                   │
│  ② 力控闭环（阻抗控制）→ 0.01N 级，1000Hz                    │
│     部署：MCU 本地（不经过网络）                              │
│  ③ IK 求解器（Pinocchio）→ 末端位姿→关节角度                  │
│     部署：Jetson 本地                                         │
└──────────────────────────────────────────────────────────────┘
```

### 数据流（完整链路）

```
人类操作员输入："把A烧杯粉末取出来，装到B微量杯里，用刮刀刮平"
    │
    ↓
☁️ LLM (云端 API, 2-5s)
    理解语义 → 分解为 5 个 task → 输出符号指令
    [
      {"skill":"pick",     "target":"spatula"},
      {"skill":"scoop",    "target":"beaker_A"},
      {"skill":"pour_powder", "target":"beaker_B"},
      {"skill":"scrape",   "target":"beaker_B", "force":"0.1-0.5N"},
      {"skill":"place",    "target":"spatula", "dest":"tool_rack"}
    ]
    │
    ↓
🏢 场景感知 (服务器 GPU, 30-80ms)
    指令 → 启动摄像头 → 图像回传 → SAM2+DINOv2 → 输出物体位姿
    │
    ↓
🏢 技能策略 → 🤖 Jetson (服务器推理 10-30ms, 轨迹下发 0.5ms)
    物体位姿 + 当前关节角 → Diffusion Policy → 200步关节轨迹
    │
    ↓
🤖 MCU 执行 (本地 200Hz, 1秒完成)
    同时：力控闭环 1000Hz (本地) + 视觉伺服 30Hz (Jetson)
    │
    ↓
    执行完成 → 🤖 Jetson 上报状态 → 🏢 服务器判断 → 进入下一 task
```

## 三、触觉融合方案

### 触觉不单独建模型，作为条件信号喂入 Diffusion Policy

```
原始数据流：
    触觉手套 124 点 (15Hz, 0-255)
        ↓
    12×12×3 编码矩阵
        │ Ch1 = 当前压力 P(t)
        │ Ch2 = 压力变化率 P(t)-P(t-1)
        │ Ch3 = 局部振动强度 var(P, t-4到t)
        ↓
    4 层 CNN:
        Conv(3→16, 3×3) → MaxPool(2×2)
        Conv(16→32, 3×3) → MaxPool(2×2)
        Flatten → Linear → 64 维特征向量
        ↓
    ┌──────────────────────────────┐
    │ 条件编码器 (352-dim)          │
    │ ① 图像特征: 256-dim          │
    │ ② 关节角度: 16-dim           │
    │ ③ 触觉编码: 64-dim  ← 加入  │
    │ ④ 指令编码: 16-dim           │
    └──────────────┬───────────────┘
                   ↓
         Diffusion Policy U-Net
         随机噪声 → 逐步去噪 → 干净轨迹
```

### 触觉在三个阶段的作用

| 阶段 | 触觉的作用 |
|------|-----------|
| **采集（人手示教）** | 触觉手套记录人手力度分布 → 训练时作为 learn signal |
| **训练（BC → RL）** | 条件信号的一部分 → 模型学会"多大力对应什么动作" |
| **执行（真机推理）** | 灵巧手触觉传感器实时反馈 → MCU 力控闭环修正 grip force |

## 四、训练策略

### 三阶段训练法（技能策略模型）

```
阶段 1: BC (行为克隆)
  方法：人手示教（触觉手套+遥操作或摄像头）
  数据：每个技能 500-2000 次成功示教
  目标：模型学会"像人那样做"
  工具：Diffusion Policy 官方实现

阶段 2: RL (强化学习)
  方法：MuJoCo 仿真环境 + MJX (GPU 加速)
  数据：10万-100万步（GPU 几分钟跑完）
  目标：优化路径平滑度/成功率/效率，超越人手表现
  工具：SB3 + PPO

阶段 3: 真机微调
  方法：真机上跑 50-200 次，记录失败案例
  数据：失败轨迹 + 人工修正
  目标：弥合 sim-to-real gap
```

### 需要训练的模型（共 3 个）

| 模型 | 训练方法 | 数据规模 | 触觉参与？ | 底层架构 |
|------|---------|---------|-----------|---------|
| ① 场景感知 | 微调（不是训练） | 500-2000 张标注图 | ❌ 纯视觉 | SAM2 + DINOv2 |
| ② 技能策略 | BC + RL + 真机微调 | 500-2000次示教 + 100万步RL | ✅ 核心输入 | Diffusion Policy |
| ③ 技能选择 | 规则 + 少量监督 | 几乎零成本 | ❌ | 轻量 MLP，几百行 |

**LLM 不训练**，买 API 服务直接用（GPT-5 / Claude-4 级，云部署按量付费）。

## 五、部署方案

### 物理部署

```
☁️ 云端 (阿里云/火山引擎)
    LLM API → SOP 理解 + 任务规划 + 安全监控
    优点：免部署，按量付费，自动升级

🌐 10GbE 局域网

🏢 本地服务器 (公司/浙大机房)
    1-2 张 RTX 4090 / A6000
    场景感知推理 (GPU 0) + 技能策略推理 (GPU 1)
    数据记录 / 系统状态管理

🌐 WiFi6 / 有线

🤖 机器人本体 (G1-D)
    ├── Jetson Orin 16G
    │   ├── Diffusion Policy 推理 (本地 10-30ms)
    │   ├── AprilTag 视觉伺服 (30Hz)
    │   ├── ROS2 通信网关
    │   └── 本地 fallback 安全策略
    │
    └── 实时控制器 MCU
        ├── 力控闭环 (1000Hz, 不经过网络)
        ├── 关节控制 (EtherCAT)
        └── 安全监测 (独立急停)
```

### 延迟链路分析

| 链路 | 总延迟 | 关键路径 |
|------|--------|---------|
| LLM → 任务规划 | 2000-5000ms | 云端 LLM 推理（占 95%） |
| 场景感知 → 物体定位 | 30-80ms | 本地服务器 GPU 推理 |
| 技能生成 → 轨迹下发 | 10-30ms + 0.5ms 网络 | Diffusion Policy + ROS2 |
| 力控闭环 | < 2ms | MCU 本地，不经过网络 |
| 视觉伺服修正 | ~40ms | Jetson 本地 AprilTag |

## 七、实施路线

```
Phase 1 (0-3月) — 快速跑通
  使用 LabVLA 跑通一个化学操作 Demo
  目的：证明概念，给投资人/浙大看

Phase 2 (3-8月) — 搭分层骨架
  开发中间件层（IK/视觉伺服/力控闭环）
  触觉手套示教采集第一批技能数据
  训练第一个技能模型 (pick)
  Diffusion Policy 替代 LabVLA 的动作生成

Phase 3 (6-12月) — LLM 接入
  接入 GPT-5/Claude-4 API
  24 步 DRIFTS 流程 SOP → LLM 可读
  跑通一条完整实验流程

Phase 4 (12-24月) — 数据飞轮
  技能库 3→20+ 技能
  每做一次实验，数据自动回流
  越用越强

Phase 5 (24-60月) — 世界模型
  积累百万级实验数据
  训练化学实验室专属世界模型
  替代 MuJoCo，系统能做实验预演
```

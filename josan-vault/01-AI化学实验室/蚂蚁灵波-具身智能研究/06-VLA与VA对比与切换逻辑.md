# VLA vs VA：本质差异与切换逻辑

> 相关笔记：[[VLA-视觉语言动作模型]] | [[VA-视频动作模型]] | [[为什么拆成六个模型]]

---

## 一、本质差异

### 一句话区分

> VLA像"**看图说话**"——每看一张新图做一次决策，没有上下文记忆。
> VA像"**看视频学习**"——记得之前发生了什么，因为有视频序列的时间连续性。

### 完整对比表

| 对比维度 | VLA | VA |
|---------|-----|----|
| **基底模型** | 多模态大模型（VLM） | 视频生成模型（VideoGen） |
| **核心逻辑** | "看图+听话→决定动作" | "看视频→学会动作→记住上下文" |
| **对齐顺序** | Vision↔Language → Action | Video↔Action → Language |
| **有记忆吗？** | ❌ 没有，只看当前帧 | ✅ 有，序列自回归天然记忆 |
| **能计数吗？** | ❌ 擦几次盘子？不知道 | ✅ 能记住做了几次 |
| **推理速度** | ✅ ~100ms，能跑端侧 | ⚠️ ~300-400ms，需异步优化 |
| **指令打断** | ✅ 用户可以中途改指令 | ❌ 一镜到底，很难中途打断 |
| **幻觉问题** | ✅ 相对少 | ❌ 视频生成会有"无中生有" |
| **部署难度** | ✅ 低，可直接上真机 | ⚠️ 高，需要异步推理框架 |
| **蚂蚁定位** | **当下务实路线** | **未来探索路线** |

### 对齐路径示意图

```
VLA：     Vision → Language → [对齐] → Action
           ↑          ↑ 
        先让"看"和"说"对上，再说怎么动

VA：      Video → Action → [对齐] → Language
           ↑          ↑
        先让"看视频"和"怎么动"对上，再理解语言指令
```

## 二、为什么需要VA？VLA不够吗？

VLA有三个核心局限，VA正好解决：

### 1. 无记忆 → 无法处理"几次"概念
擦盘子、开关盒子等任务，VLA会陷入死循环。

### 2. 无时间建模 → 无法区分"开始"和"结束"
状态相同的不同时间点，VLA无法区分"还没开始"和"已经完成"。

### 3. 缺乏动态先验 → 学不会"动作的感觉"
VLA基于静态图像训练，缺乏视频中的运动信息（Dynamic Prior）。

## 三、VLA↔VA切换逻辑

蚂蚁通过**Brain Orchestrator（大脑编排器）**实现模型切换。

### 切换原则

```
               ┌──────────────────────┐
               │ Brain Orchestrator    │
               │  (模型路由/切换决策器)  │
               └──┬───────┬───────┬────┘
                  │       │       │
        ┌─────────┘       │       └──────────┐
        ▼                 ▼                  ▼
   ┌─────────┐     ┌──────────┐     ┌────────────┐
   │ VLA     │     │ VA       │     │ World      │
   │ 端侧实时 │     │ 边缘侧   │     │ 云端离线    │
   └─────────┘     └──────────┘     └────────────┘
        │                 │                │
        └─────────────────┴────────────────┘
                  共享感知层
              (Vision + Depth)
```

### 切换条件（规则驱动）

```
IF 任务类型 = "单步操作" → 路由到 VLA
IF 任务类型 = "时序追踪" → 路由到 VA
IF 需要评估 → 调用 World
IF 置信度低于阈值 → 触发双模型仲裁
```

### 仲裁机制

```
当VA和VLA的判断不一致时：
  方式1：置信度比较 → 谁的置信度高听谁的
  方式2：切换到人工介入
```

### 未来方向

蚂蚁目前以**规则驱动**为主，未来计划训练一个 **Router Agent（小模型）** 自动判断调用哪个模型。

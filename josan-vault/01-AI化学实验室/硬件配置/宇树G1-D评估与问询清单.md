## 二、技术评估

### ✅ 符合项

| 维度 | 说明 |
|------|------|
| 双臂 7-DOF | 动作空间 8→16，Diffusion Policy 双臂支持 |
| 手臂负载 3kg | 拿烧杯/移液枪/微量杯足够 |
| 轮式底盘 | 原地360°旋转，1.5m/s，通过95%通道 |
| 高度可调 1260-1680mm | 覆盖实验台面 |
| Jetson Orin 16G (100 Tops) | Diffusion Policy (500MB) 本地推理 OK |
| 传感器 | 双目+手腕相机+深度+激光雷达，足够丰富 |

### ⚠️ 待确认

| 风险点 | 问题 | 缓解方案 |
|--------|------|---------|
| **力控精度** | Dex3-1 触觉下限 10g(~0.1N)，DRIFTS 需求 0.05N | 预算充足则接受，视觉伺服+外部力控补 |
| **末端精度** | 0.1°关节 × 450mm臂展 ≈ 0.78mm，需求±0.15mm | AprilTag 精对准拉到 ±0.05mm（手腕相机已带） |
| **数采平台** | 训练/推理暂不支持，需后续开发 | LabVLA/Diffusion Policy 独立运行，不用它的数采 |
| **SDK 开放度** | 是否支持底层控制、绕过数采软件 | 见问询清单 |

## 三、技术问询清单（宇树会面前必读）

### 🚦 6 个关键判断题

| # | 问题 | 为什么重要 | 底线 |
|---|------|----------|------|
| ① | **提供底层 Python/C++ SDK？** | Diffusion Policy 要能直接发指令 | ✅ 必须 Yes |
| ② | **支持末端笛卡尔空间控制？** | 输出的是末端位姿 delta，不是关节角 | ✅ 必须 Yes |
| ③ | **控制频率 ≥ 100Hz？** | 精细操作需要高频闭环 | ✅ 必须 Yes |
| ④ | **ROS/ROS2 驱动支持？** | 集成现有 AI 栈的工业标准 | ✅ 必须 Yes |
| ⑤ | **灵巧手触觉数据可实时回读？** | 力控 0.05-0.10N 需要闭环反馈 | ⚠️ 强烈建议 Yes |
| ⑥ | **能绕过数采软件直接操控？** | 训练推理是自己的管道，不走宇树平台 | ✅ 必须 Yes |

### 完整问题清单

<details>
<summary>点击展开详细问题</summary>

#### 第一优先级 — 决定能否集成

**Q1: 底层 SDK / API 开放程度**
- G1-D 是否提供底层控制 SDK（C++/Python）？
- 能否通过 API 直接发送关节角度指令（非遥控器模式）？
- 是否支持末端位姿控制（笛卡尔空间）？
- 电机通信协议：EtherCAT / CAN / 自有协议？

**Q2: 控制模式与频率**
- 支持哪几种控制模式？（位置/速度/力矩）
- 控制循环频率是多少？（Hz）
- 是否有实时模式（RTOS / PREEMPT_RT）？
- 控制指令到执行器响应的延迟？（ms）

**Q3: 重复定位精度**
- 实测重复定位精度是多少？（官网没标）
- 是否提供末端位姿的闭环反馈？
- 关节编码器分辨率？

#### 第二优先级 — 力控与灵巧手

**Q4: 灵巧手力控规格**
- Dex3-1 触觉传感器采样频率？（Hz）
- 触觉数据能否实时回读到上位机？
- 是否支持主动力控 / 阻抗控制 / 导纳控制？
- 灵巧手控制频率？（Hz）

**Q5: 力控闭环**
- 手臂本体是否支持力矩控制？
- 有没有关节力矩传感器？（还是仅电流估算？）

#### 第三优先级 — 集成与部署

**Q6: ROS/ROS2 支持**
- 是否提供 ROS/ROS2 驱动包？
- 支持哪些 topic/service？
- 是否有第三方社区方案？

**Q7: 上位机与算力**
- Jetson Orin 能否替换为自研算法？
- 能否直连外部 GPU 服务器（以太网）？

**Q8: 数采平台 API**
- 是否提供 API/SDK 导出原始数据？
- 数据格式？能否对接外部训练管道？

**Q9: 手眼标定**
- 手腕相机到末端的手眼标定是否预标好？
- 有没有标定工具？

## 四、问询话术参考

### 快速判断对方技术水平

**如果对方是销售/商务**，先问这 3 句：

> ① "开发者文档有没有？SDK 长啥样？" → 懵了 => 要技术联系人

> ② "我们不用你们的数采软件，直接 SDK 控制机器人行不行？" → 核心开放度测试

> ③ "ROS 驱动有没有？给个 GitHub 链接看看。" → 快速验证技术深度

### 总结一句话

> "我们有自己的 AI 模型（Diffusion Policy + LLM）运行在 Ubuntu + GPU 服务器上，需要 G1-D 提供一个开放的底层控制接口（Python SDK / ROS），让我们直接发关节或末端指令，同时灵巧手触觉数据能实时流回来。如果可以，具体延迟和精度是多少？"
